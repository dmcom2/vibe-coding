객체 배열 — 퀴즈 데이터 관리

여러 속성을 가진 데이터를 배열로 관리하는 방법

객체는 여러 관련 정보를 하나로 묶는 방법입니다. 객체 배열은 여러 객체를 배열로 모아서 퀴즈 문제처럼 비슷한 구조의 데이터를 관리합니다.
// 퀴즈 데이터 (객체 배열, id로 구분) let QUESTIONS = [ { id: 1, question: 'HTML은 프로그래밍 언어이다', answer: false, // X (마크업 언어) explanation: 'HTML은 마크업 언어입니다.' }, { id: 2, question: 'CSS는 색상과 레이아웃을 담당한다', answer: true, // O explanation: 'CSS는 스타일을 담당합니다.' } ]; // 접근 방법 QUESTIONS[0].question // 첫 번째 문제 QUESTIONS.length // 총 문제 수
🆚

배열 vs 객체 vs 객체 배열

[] 배열: 순서 있는 목록
['홍길동', '김철수']

{} 객체: 키-값 쌍
{name:'홍', age:30}

[{}] 객체 배열: 둘의 조합
[{name:'홍',score:90},...]

📺

화면 전환 패턴 — showScreen()

여러 화면(시작/퀴즈/결과/관리)을 하나의 HTML로 관리

HTML+JS <!-- HTML: 화면 4개, 하나만 표시 --> <div class="screen active" id="start-screen">... <div class="screen" id="quiz-screen">... <div class="screen" id="manage-screen">... /* CSS */ .screen { display: none; } .screen.active { display: block; } // JavaScript function showScreen(id) { document.querySelectorAll('.screen') .forEach(s => s.classList.remove('active')); document.getElementById(id) .classList.add('active'); } showScreen('manage-screen');

퀴즈 상태 변수들

currentIndex
현재 몇 번째 문제인지 (0부터 시작)
score
맞은 개수 (정답 시 +1)
wrongList
틀린 문제 번호를 저장하는 배열
editingId
문제 관리 화면에서 지금 수정 중인 문제의 id
⭕

정답 처리 & 다음 문제

답 체크 → 피드백 표시 → 다음 문제 이동 흐름

function checkAnswer(userAnswer) { const q = QUESTIONS[currentIndex]; const isCorrect = (userAnswer === q.answer); if (isCorrect) { score++; } else { wrongList.push({ index: currentIndex + 1, q }); } // 아이콘·문구·해설을 화면에 반영 title.textContent = isCorrect ? '정답입니다!' : '오답입니다!'; showScreen('feedback-screen'); } function nextQuestion() { currentIndex++; if (currentIndex >= QUESTIONS.length) { showResult(); // 문제 소진 → 결과 화면 } else { showQuestion(); // 다음 문제 표시 showScreen('quiz-screen'); } }
✏️

문제 관리 — 배열 CRUD

같은 폼 하나로 "추가"와 "수정"을 모두 처리합니다

let editingId = null; // null이면 추가 모드 function saveQuestion() { const text = ...value.trim(); if (editingId === null) { // 추가: 배열 끝에 새 항목 QUESTIONS.push({ id: Date.now(), question: text, ... }); } else { // 수정: id로 찾아서 속성만 변경 const target = QUESTIONS.find(q => q.id === editingId); target.question = text; } localStorage.setItem('ox-questions', JSON.stringify(QUESTIONS)); renderManageList(); } function deleteQuestion(id) { QUESTIONS = QUESTIONS.filter(q => q.id !== id); localStorage.setItem('ox-questions', JSON.stringify(QUESTIONS)); renderManageList(); }
editingId 하나로 두 가지 모드 구현!

id가 null이면 "새 문제 추가" 모드, id가 있으면 "그 문제 수정" 모드로 같은 저장 버튼이 다르게 동작합니다.
💾

편집 내용도 자동 저장

추가·수정·삭제할 때마다 localStorage에 통째로 저장하므로, 새로고침해도 내가 편집한 문제 그대로 남아있습니다.

🔤 "한글이 깨져 보여요"

🤖 만능 해결법: 오류 메시지나 이상한 화면을 그대로 복사(캡처)해서 AI에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요. 대부분 해결됩니다.

코드 핵심 설명

index.html 파일에서 찾아봐야 할 핵심 부분

① 정답 확인 (checkAnswer)

function checkAnswer(userAnswer) { const q = QUESTIONS[currentIndex]; const isCorrect = (userAnswer === q.answer); if (isCorrect) { score++; } else { wrongList.push({ index: currentIndex + 1, q }); } showScreen('feedback-screen'); }
• userAnswer === q.answer — 버튼값과 정답을 비교만 하면 채점 끝
• 틀렸을 때 wrongList에 문제 번호를 기록해 결과 화면에서 재사용

② 문제 수 0개일 때 방어 코드

function startQuiz() { if (QUESTIONS.length === 0) { alert('문제가 없습니다. 먼저 추가해주세요!'); openManage(); return; } currentIndex = 0; score = 0; showQuestion(); showScreen('quiz-screen'); }
• 사용자가 문제를 전부 지워버려도 게임이 깨지지 않도록 미리 막아주는 코드
• 이런 예외 상황 처리가 실제 서비스 코드에서 가장 중요합니다
