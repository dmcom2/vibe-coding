오늘 나오는 용어 미리보기

외우지 마세요 — 눈에만 익혀 두면 수업이 술술 풀립니다

📌 TF-IDF

한 문서에 자주 나오고(TF) 다른 문서엔 드문(IDF) 단어일수록 무게를 크게 줍니다. '주세요'처럼 흔한 말은 저절로 가벼워집니다.

📌 코사인 유사도

두 문서를 단어 무게의 화살표로 보고 사이 각도를 잽니다. 1이면 같은 방향(같은 내용), 0이면 무관.

📌 린트 (Lint)

코드의 실수를 규칙으로 찾아 주는 검사기처럼, 프롬프트의 빠진 요소를 규칙 8개로 찾아 점수를 매깁니다.

📌 LCS (최장 공통 부분열)

두 글에서 순서를 지키며 겹치는 가장 긴 단어 줄. 여기에 없는 단어가 곧 추가·삭제된 부분입니다.

📌 베타 분포 · 신용구간

성공 s번·실패 f번이면 성공률은 Beta(1+s, 1+f). 95% 신용구간은 "참 성공률이 이 안에 있을 확률 95%"입니다.

📌 톰슨 샘플링

각 버전의 분포에서 성공률을 하나씩 뽑아 가장 높은 버전을 씁니다. 잘하는 버전에 트래픽이 자연스럽게 몰립니다.

핵심 기술 ① — 한글 바이그램 TF-IDF 검색

형태소 분석기 없이도 '회의'로 '회의록'을 찾는 가장 간단한 방법
// 한글 단어는 두 글자씩 끊는다 function tokens(text) { const out = []; for (const w of text.match(/[가-힣]+|[a-z][a-z0-9]+/g)) if (/[가-힣]/.test(w)) for (let i = 0; i < w.length - 1; i++) out.push(w.slice(i, i + 2)); // 회의록 → 회의, 의록 else out.push(w); return out; }
// 제목×3 · 설명×2 · 태그×2 · 본문×1 가중 const idf = t => Math.log((N + 1) / (df[t] + 1)) + 1; const w = (1 + Math.log(tf)) * idf(t); // 길이 1로 정규화한 뒤 내적 = 코사인 const cosine = (a, b) => { let s = 0; a.forEach((x, t) => s += x * (b.get(t) || 0)); return s; };
🔎 완성 예제 기준 '회의 정리'를 검색하면 회의 내용 핵심 정리(0.37), 회의록 요약 정리(0.28) 순으로 나옵니다. 같은 계산으로 모든 쌍을 비교해 유사도 0.30 이상인 중복 후보 2쌍(고객 불만 응대 ↔ 고객 문의 사과 0.50 등)을 찾습니다.

핵심 기술 ② — 프롬프트 품질 린트와 {{변수}}

좋은 프롬프트의 요소를 정규식 규칙으로 바꾸면 "감"이 "점수"가 됩니다
// 8개 규칙 · 가중치 합 100점 const RULES = [ { k: 'role', w: 15, re: /(당신은|너는|역할|전문가)/ }, { k: 'task', w: 15, re: /(해\s?줘|주세요|하세요)/ }, { k: 'ctx', w: 15, re: /(배경|상황|목적|대상)/ }, { k: 'fmt', w: 15, re: /(형식|표로|목록|순서로)/ }, // 제약 10 · 예시 10 · 변수 10 · 길이 10 ]; const score = sum(RULES.map(r => r.re.test(body) ? r.w : 0));
// {{이름}} 또는 {{이름|선택1|선택2}} const re = /\{\{([^{}|]+)((?:\|[^{}|]*)*)\}\}/g; for (const m of body.matchAll(re)) { const name = m[1].trim(); const opts = m[2] ? m[2].split('|').slice(1) : []; // opts가 있으면 드롭다운, 없으면 입력칸 } // 입력값을 끼워 넣어 완성 프롬프트를 복사
🧪 완성 예제 기준 '주간 업무 보고서 작성'은 v1 45점 → v2 80점 → v3 100점으로 오를 때 실제 성공률도 52% → 76% → 94%로 올랐습니다. 전체 버전의 품질 점수와 성공률 상관계수는 r = 0.84입니다.

핵심 기술 ③ — LCS로 단어 단위 변경 내역 만들기

Git이 코드 변경을 보여주는 원리를 그대로 프롬프트 버전에 적용합니다
// 공백을 살려서 단어로 자르기 const A = a.split(/(\s+)/), B = b.split(/(\s+)/); // L[i][j] = A[i..], B[j..]의 LCS 길이 (뒤에서부터) for (let i = n - 1; i >= 0; i--) for (let j = m - 1; j >= 0; j--) L[i][j] = A[i] === B[j] ? L[i + 1][j + 1] + 1 : Math.max(L[i + 1][j], L[i][j + 1]);
// 앞에서부터 따라가며 = / − / + 판정 while (i < n && j < m) { if (A[i] === B[j]) { push('=', A[i]); i++; j++; } else if (L[i + 1][j] >= L[i][j + 1]) push('-', A[i++]); // 삭제 (빨강) else push('+', B[j++]); // 추가 (초록) } // 남은 꼬리는 전부 삭제·추가 // 칸 수가 36만을 넘으면 줄 단위로 비교
🔀 완성 예제 기준 '주간 업무 보고서 작성' v2 → v3은 44단어 추가, 3단어 삭제입니다. "동안 제가 한"이 "동안의 … 팀장 보고용"으로 다듬어지고 제약 조건·예시 섹션이 붙은 것을 한눈에 볼 수 있습니다.

핵심 기술 ④ — 베이지안 A/B 실험과 톰슨 샘플링

"새 버전이 더 좋을 확률은 몇 %인가?"에 직접 답하는 방법
// 사후분포 Beta(1+성공, 1+실패)에서 1만 번 뽑기 for (let k = 0; k < 10000; k++) { let best = null; for (const a of arms) { a.smp[k] = randBeta(a.a, a.b, rng); if (!best || a.smp[k] > best.smp[k]) best = a; } best.win++; // P(최고) = win / 1만 } // 95% 신용구간 = 정렬한 표본의 2.5%, 97.5% 지점 // Beta = X/(X+Y), X·Y는 감마 난수(마사글리아-창)
// 톰슨 샘플링: 매 실행마다 한 번씩 뽑아 최댓값 선택 for (let t = 1; t <= 300; t++) { const pick = argmax(arms.map((a, i) => randBeta(1 + s[i], 1 + f[i], rng))); if (rng() < arms[pick].rate) s[pick]++; else f[pick]++; } // 처음엔 골고루 → 점점 좋은 버전에 몰림
🧫 완성 예제 기준 '고객 불만 응대 답변'은 v3 성공률 83%(46회) vs 기본 v2 60%(67회) — v3이 최고일 확률 99% 이상, 개선폭 +21.8%p(95% 구간 5.7~37.4%p)라 기본 버전을 바꿉니다. 반면 'SNS 홍보 문구 생성'은 P(최고) 59%로 아직 "진행 중"입니다.

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 평가 기준과 통계를 시키는 법"을 배웁니다

POINT 1 — 규칙은 키워드와 점수까지

"품질 점수를 매겨줘"가 아니라 규칙 8개의 정규식 키워드와 가중치를 적었습니다. 그래야 강사와 수강생의 점수가 같습니다.

POINT 2 — 샘플 데이터에 정답을 숨긴다

"숨은 성공 확률 = 0.30 + 0.55 × 품질/100"을 넣었습니다. 분석 화면에서 학습자가 품질과 성과의 관계를 스스로 발견하게 됩니다.

POINT 3 — 통계 방법을 이름으로 지정

"A/B 테스트해줘"라고만 하면 t검정·카이제곱 등 AI마다 다른 방법을 씁니다. Beta 사전분포·표본 수·시드까지 정했습니다.

POINT 4 — 오해를 막는 표시 규칙

"99.5% 이상은 '99% 이상'"처럼 표시 방식을 정했습니다. 반올림된 100%는 "절대 확실"로 잘못 읽히기 쉽습니다.

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요
🔎 "검색 결과가 하나도 안 나와요"

한글을 공백으로만 나누면 '회의'와 '회의록'이 다른 단어가 됩니다. "한글 단어는 두 글자씩 끊어서(바이그램) 색인해줘"라고 요청하세요.

⌨️ "변수 칸에 입력하면 글자가 끊겨요"

입력할 때마다 입력칸 HTML을 새로 만들면 포커스가 사라집니다. "변수 목록이 바뀔 때만 입력칸을 다시 만들고, 값 입력 땐 미리보기만 갱신해줘"라고 요청하세요.

🎲 "새로고침마다 숫자가 바뀌어요"

Math.random()을 쓰면 샘플 데이터와 P(최고)가 매번 달라집니다. 시드 고정 난수(mulberry32)를 쓰고, 한 번 만든 데이터는 localStorage에 저장하세요.

📋 "복사 버튼이 안 돼요"

파일을 더블클릭해서 열면(file://) 클립보드 API가 막힙니다. Live Server로 열거나 "복사 실패 시 textarea + execCommand로 대체해줘"라고 요청하세요.

🤖 만능 해결법: F12 → Console의 빨간 오류나 이상한 화면을 그대로 복사(캡처)해서 Antigravity에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요.
