📌 하비 볼

원을 채운 정도로 수준을 나타내는 기호. 컨설팅 보고서와 제조 현장의 스킬맵에서 표준처럼 씁니다. 여기서는 0~5단계.

📌 직무 목표 · 달성률

직무마다 필요한 역량과 목표 수준(예: 프론트엔드 개발자 React/Vue 4). 목표 이상인 역량의 비율이 목표 달성률입니다.

📌 전문가 · 실무자

수준 4 이상은 전문가(가르칠 수 있음), 3 이상은 실무자(혼자 할 수 있음). 기준은 설정에서 바꿀 수 있습니다.

📌 버스 팩터

"몇 명이 동시에 빠지면 일이 멈추는가". 핵심 역량 중 전문가가 가장 적은 역량의 전문가 수로 계산합니다. 1이면 위험.

📌 가용률 · FTE

기존 업무를 빼고 새 프로젝트에 쓸 수 있는 시간 비율. 가용률 합 ÷ 100이 FTE(전일 근무 인원 환산)입니다.

📌 탐욕법 (Greedy)

매 단계에서 지금 가장 이득이 큰 선택을 하는 방법. 편성에서는 남은 요구를 가장 많이 채우는 사람을 한 명씩 뽑습니다.

핵심 기술 ① — 하비 볼과 목표 달성률

수준은 원의 채움으로, 목표는 바깥 고리로 — 한 칸에 두 정보를 겹친다
// 수준/5 만큼 부채꼴을 채운 SVG 원 function harvey(lv, tgt) { const a = lv / 5 * Math.PI * 2; // 12시 방향부터 const x = 12 + r * Math.sin(a), y = 12 - r * Math.cos(a); pie = `M12 12 L12 ${12-r} A${r} ${r} 0 ${a > π ? 1 : 0} 1 ${x} ${y} Z`; // 목표가 있으면 고리: 달성 = 남색 실선, 미달 = 빨간 점선 ring = tgt ? (lv >= tgt ? 'meet' : 'miss') : ''; }
// 목표 달성률 = 목표 이상인 역량 ÷ 목표가 있는 역량 function achievement(m) { const t = skills.filter(s => targetOf(m, s) > 0); return t.filter(s => lvOf(m, s) >= targetOf(m, s)).length / t.length; } // 목표는 사람이 아니라 '직무'에 붙는다 const targetOf = (m, s) => roles[m.role][s.id] || 0;
🔵 완성 예제 기준 매트릭스는 384칸(24명 × 16개)이고, 그중 직무 목표가 걸린 칸은 121칸, 목표에 못 미친 칸은 31칸입니다. 팀 평균 목표 달성률은 75%, 100% 달성자는 8명, 가장 낮은 사람은 신아름 · 전하린 · 장우석(40%)입니다.

핵심 기술 ② — 개발 우선순위와 멘토 추천

"무엇부터 키울까"를 점수로 — 모자란 정도 × 역량의 중요도 + 본인의 관심
// 목표에 못 미친 역량만 골라 우선순위 점수 function gapItems(m) { return roleTargets(m) .map(s => ({ s, gap: targetOf(m, s) - lvOf(m, s) })) .filter(g => g.gap > 0) .map(g => ({ ...g, pri: g.gap * g.s.crit // 핵심 3 · 중요 2 · 일반 1 + (itOf(m, g.s) === 3 ? 0.5 : 0) })) // 관심 높음 .sort((a, b) => b.pri - a.pri); }
// 멘토: 그 역량의 전문가(수준 4+) 중에서 function mentorsFor(m, s) { return members .filter(x => x !== m && lvOf(x, s) >= 4) .sort((a, b) => lvOf(b, s) - lvOf(a, s) // 수준 높은 순 || b.avail - a.avail // 여유 있는 순 || (b.team === m.team) - (a.team === m.team)) .slice(0, 2); }
🌱 완성 예제 기준 프론트엔드 개발자 윤재원의 달성률은 60%입니다. 1순위는 React/Vue(현재 3 → 목표 4, 갭 1 × 핵심 3 + 관심 0.5 = 3.5점, 멘토 최민준 · 황보라), 2순위는 문제 해결(2.5점, 멘토 강수진 · 이준혁)입니다.

핵심 기술 ③ — 커버리지 리스크와 버스 팩터

"이 일을 할 줄 아는 사람이 몇 명인가"를 역량마다 세고, 한 명이 빠진 세상을 다시 계산한다
// leave = 빠진 것으로 가정할 팀원들 function coverage(s, leave) { const e = members.filter(m => !leave.has(m.id) && lvOf(m, s) >= 4).length; return e === 0 ? '공백' : e === 1 ? '단일 의존' : e < s.min ? '부족' : '안정'; }
// 버스 팩터: 핵심 역량(중요도 3) 중 가장 적은 전문가 수 const bus = Math.min(...skills .filter(s => s.crit === 3) .map(s => coverage(s, leave).e)); // 후계 후보: 전문가 바로 아래(3) + 관심 높음 const next = members.filter(m => lvOf(m, s) === 3 && itOf(m, s) === 3);
🚌 완성 예제 기준 버스 팩터는 1명입니다. 머신러닝은 공백, 보안(오태윤)과 UI 디자인(김다인)은 단일 의존, 코칭·멘토링은 전문가 2명 / 최소 3명으로 부족입니다. 퇴사 시뮬레이션에서 오태윤을 빼면 보안이 공백이 되어 버스 팩터가 0명이 되고, 보안의 후계 후보로 문가영 · 배지훈이 추천됩니다.

개발 우선순위 = (목표 − 현재) × 중요도 + (관심도 높음이면 가산점 0.5), 목표에 못 미친 역량만 · 정렬: 점수 → 갭 → 역량 순서 - 멘토: 본인 제외, 그 역량 수준이 전문가 기준 이상인 사람, 수준 높은 순 → 가용률 높은 순 → 같은 팀 먼저 → 이름순, 2명 리스크 - 역량마다 전문가 수 e: 0이면 공백, 1이면 단일 의존, 최소 인원 미만이면 부족, 그 외 안정 - 위험한 순 정렬: 공백 → 단일 의존 → 부족 → 안정, 같으면 중요도 높은 순 → 전문가 적은 순 → 역량 순서 - 버스 팩터 = 중요도 3(핵심) 역량들의 전문가 수 중 최솟값 - 핵심 인재 = 어떤 역량의 유일한 전문가 - 후계 후보 = 수준이 (전문가 기준 − 1)이고 관심도 높음, 1년 성장 큰 순 → 가용률 → 이름 - 시뮬레이션은 고른 팀원을 빼고 위 계산을 그대로 다시 함 자동 편성 - 후보 = 가용률이 최소 가용률(20%) 이상인 팀원 - 요구마다 남은 인원 rem을 두고, 최대 인원이 될 때까지 또는 rem이 모두 0이 될 때까지 반복 · 이득 = rem > 0인 요구 중 그 사람이 충족하는(수준 ≥ 요구 수준) 요구마다 1 + 0.1 × (수준 − 요구 수준)을 더한 값 · 이득이 가장 큰 사람을 추가 (같으면 가용률 높은 순 → 이름순), 이득이 0이면 멈춤 · 추가한 사람이 충족한 요구의 rem을 1씩 줄임 - 충족 판정: 요구마다 팀원 중 충족자 수 ≥ 요구 인원, FTE = 가용률 합 ÷ 100 - 교육 후보 = 수준이 (요구 수준 − 1)이고 관심도 보통 이상, 가용률 최소 이상, 관심도 높은 순 → 가용률 → 이름 분기 이력 - 분기 4개: 2025 Q4 · 2026 Q1 · 2026 Q2 · 2026 Q3(현재) - 과거 3분기는 현재 수준에서 거꾸로 만들기: mulberry32(시드 505) · 팀원 순서 → 역량 순서 → 1 · 2 · 3분기 전 순서로 난수를 하나씩 뽑음 (조건과 관계없이 항상 뽑기) · 그 시점 수준이 2 이상이고 난수 < 관심도별 확률(낮음 0.03 · 보통 0.07 · 높음 0.14)이면 1 낮춤 · 1분기 전 값에서 이어서 2분기 전, 3분기 전을 계산 (3분기 전 = 2025 Q4) - 1년 성장 = 현재 − 2025 Q4, 분기별 달성률은 그 분기 수준으로 계산 (목표는 현재 직무 기준) - 변경 기록은 최근 300건, 되돌리기는 가장 최근 기록부터 ■ 5. 샘플 데이터 (숫자를 바꾸지 마세요) 읽는 법 - 한 줄 = 이름 · 팀 · 직무 · 가용률 · 수준 16자리 · 관심도 16자리 - 16자리는 1번 역량 표의 순서: JavaScript, React/Vue, SQL/DB, 클라우드·DevOps, 테스트 자동화, 보안, 데이터 분석, 데이터 시각화, 머신러닝, UX 리서치, UI 디자인, 서비스 기획, 프로젝트 관리, 발표/커뮤니케이션, 문제 해결, 코칭·멘토링 개발팀 - 프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 인력 판단 로직을 시키는 법"을 배웁니다

POINT 1 — 목표를 '사람'이 아니라 '직무'에

직무별 목표표 하나만 적으면 24명의 달성률 · 갭 · 우선순위가 모두 자동으로 나옵니다. 사람마다 목표를 적으면 관리가 불가능해집니다.

POINT 2 — 위험의 정의를 숫자로

"위험한 역량을 알려줘" 대신 전문가 0명 = 공백, 1명 = 단일 의존, 최소 미만 = 부족으로 적었습니다. 기준이 있어야 모두가 같은 결론을 봅니다.

POINT 3 — 동점 처리까지 적는다

멘토 · 편성 · 후계 후보에 "같으면 가용률 → 이름순"을 적었습니다. 이것이 없으면 새로고침할 때마다 추천이 바뀌어 신뢰를 잃습니다.

POINT 4 — 데이터는 표 그대로

384칸을 "그럴듯하게 만들어줘"라고 하면 매번 다른 팀이 나옵니다. 한 줄에 한 사람, 16자리 숫자로 넣으면 모두의 화면이 똑같아집니다.

파일 실행 방법

AI가 만든 코드를 VS Code에서 실행하고 팀장처럼 써 보기
1

폴더 열기 · Go Live

실습 폴더를 열고 index.html · style.css · script.js를 확인한 뒤 우측 하단 Go Live를 누릅니다.

2

렌즈 바꿔 보기

L 키로 수준 → 목표 갭 → 관심도 → 1년 성장을 돌려 보고, 윤재원 이름을 눌러 개발 우선순위와 멘토를 확인합니다.

3

리스크 · 편성

2번 화면에서 오태윤을 빼 보고, 3번 화면에서 두 프로젝트를 자동 편성해 교육 후보를 확인합니다.

4

신규 입사자 반영

위쪽 가져오기로 샘플 CSV를 넣고 버스 팩터가 1 → 2명으로 바뀌는지 봅니다.

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요
🔄 "역량 이름이 거꾸로 뒤집혀 보여요"

세로 글씨를 180° 돌리면 한글이 뒤집힙니다. "세로 머리글에 text-orientation: sideways를 추가해줘"라고 요청하세요.

📌 "스크롤하면 이름 열이 사라져요"

표의 첫 열과 머리글에 고정이 빠졌습니다. "행 머리글은 left:0, 역량 머리글은 top에 position: sticky로 고정해줘"를 추가하세요.

🎲 "자동 편성 결과가 매번 달라요"

이득이 같을 때 순서가 정해지지 않았습니다. "같으면 가용률 높은 순, 그다음 이름순"이라는 동점 규칙을 적어 주세요.

📂 "CSV를 넣었더니 점수가 전부 0이에요"

열 순서로 읽고 있을 가능성이 큽니다. "머리글의 역량 이름으로 열을 찾고, 모르는 열은 건너뛰어줘"라고 요청하세요.

🤖 만능 해결법: F12 → Console의 빨간 오류나 이상한 화면을 그대로 복사(캡처)해서 Antigravity에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요.

AI 프롬프트 요령 & 실습 미션

인력 데이터를 AI에게 맡길 때의 요령과 확장 과제
1

"보여 줘"가 아니라 "결정하게 해 줘"

표만 요청하면 예쁜 점수표로 끝납니다. "누가 빠지면 무엇이 비는지", "누구를 넣어야 하는지"처럼 화면이 답해야 할 질문을 먼저 적으세요.

2

추천에는 이유를 함께

"우선순위 3.5점 = 갭 1 × 핵심 3 + 관심 0.5"처럼 점수 풀이를 화면에 표시하게 하면 팀장이 추천을 믿고 씁니다.

3

미션 1: 자기평가 vs 팀장 평가

칸마다 두 점수를 받아 차이가 2 이상인 칸을 표시하고, 면담이 필요한 사람 목록을 뽑습니다.

4

미션 2: 분기 교육 계획표

개발 우선순위 1순위를 모아 역량별 교육 인원과 멘토 배정을 분기 달력으로 만들고, 멘토 한 명당 2명까지로 제한합니다.
