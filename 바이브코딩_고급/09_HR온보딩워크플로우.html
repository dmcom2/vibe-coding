오늘 나오는 용어 미리보기

외우지 마세요 — 눈에만 익혀 두면 수업이 술술 풀립니다

📌 크리티컬 패스

시작부터 끝까지 이어지는 태스크 중 가장 긴 경로. 이 경로의 태스크가 하루 늦으면 전체 일정이 하루 늦어집니다.

📌 여유 시간(Slack)

LS − ES. 전체 일정을 늦추지 않고 미룰 수 있는 날 수. 여유가 0이면 크리티컬 패스입니다.

📌 EWMA

지수가중이동평균. 새 값 × 0.3 + 이전 평균 × 0.7처럼 최근 설문에 더 무게를 둔 평균입니다.

📌 캐플런-마이어

입사 후 날짜별로 "아직 재직 중일 확률"을 계산하는 생존 곡선. 아직 재직 중인 사람도 그때까지는 정보로 씁니다(관측 중단).

📌 로그순위 검정 · p값

두 집단의 생존 곡선 차이가 우연일 확률. p < 0.05면 "통계적으로 유의하다"고 말합니다.

📌 AUC

퇴사자와 재직자를 한 명씩 골랐을 때 퇴사자의 위험 점수가 더 높을 확률. 0.5는 동전 던지기, 1.0은 완벽.

핵심 기술 ① — 위상 정렬과 CPM(크리티컬 패스)

선행 태스크가 끝나야 다음을 할 수 있다 — 이 규칙만으로 수습 완료일이 계산됩니다
// Kahn 알고리즘: 선행이 모두 끝난 태스크부터 꺼낸다 const queue = TASKS.filter(t => !t.deps.length); while (queue.length) { const id = queue.shift(); order.push(id); SUCC[id].forEach(s => { if (--indeg[s] === 0) queue.push(s); }); } if (order.length !== TASKS.length) throw new Error('순환 의존');
// 전진: 가장 빠른 시작·종료 es = Math.max(0, ...deps.map(d => r[d].ef)); ef = es + dur; // 후진: 전체를 늦추지 않는 가장 늦은 일정 lf = Math.min(end, ...succ.map(s => r[s].ls)); ls = lf - dur; // 여유 0 → 크리티컬 패스 slack = ls - es; crit = slack === 0;
🗓️ 완성 예제 기준 표준 온보딩은 55영업일(주말 제외)이며, 크리티컬 패스는 근로계약서 → 장비 지급 → 시스템 권한 → 매뉴얼 학습 → 첫 과제 → 실무 프로젝트 → 수습 평가 → 정규 전환입니다.

핵심 기술 ② — 진행 중 일정 재계산과 지연 가정

실적(완료일)과 오늘 날짜를 넣어 CPM을 다시 돌리면 "예상 완료일"이 됩니다
// 완료 태스크: 실제 종료일로 고정 if (done[id] != null) r[id] = { es: done[id] - dur, ef: done[id] }; // 미완료 태스크: 계획대로 진행 중이되 // 오늘보다 먼저 끝날 수는 없다 else r[id] = { es, ef: Math.max(es + dur, today + 1) + (extra[id] || 0) }; // 가정 지연
// 영업일 계산: 7일 = 5영업일, 나머지만 하루씩 function bizIndex(a, b) { const days = (B - A) / DAY; let n = Math.floor(days / 7) * 5; // 남은 1~6일은 토·일을 건너뛰며 센다 ... } // 지연 = 예상 종료 − 기준 종료 (영업일)
🔍 완성 예제에서 여유 0인 첫 과제 수행을 5일 늦추면 수습 완료가 +5영업일 밀리지만, 여유 24일인 1:1 멘토링 2차는 5일 늦어져도 변화가 없습니다. 급할 때 무엇을 미뤄도 되는지 알려주는 분석입니다.

핵심 기술 ③ — 투명한 위험 점수와 검증

블랙박스 AI 대신, 가중치를 공개하고 과거 데이터로 성능을 증명합니다
// 요인을 0~1로 환산 (1에 가까울수록 위험) lvl = (4.2 - EWMA) / 2.2; // 몰입도 수준 trend = -기울기 / 0.4; // 최근 4주 하락 delay = 지연영업일 / 10; over = 기한지난태스크 / 4; gap = (멘토링공백 - 7) / 21; nom = 멘토미배정 ? 1 : 0; // 위험 점수 = Σ(가중치 × 요인) ÷ Σ가중치 × 100 // 50점↑ 고위험, 30점↑ 주의
// 과거 입사자: 45일 시점 점수 → 180일 내 퇴사? const rows = VAL.map(r => ({ p: riskOf(r.comps, w), y: r.y })); const score = auc(rows); // 좌표 탐색: 가중치를 하나씩 0~50으로 // 바꿔 보며 AUC가 오르면 채택 (3바퀴) for (const c of RISK) for (let v = 0; v <= 50; v += 5) if (auc(...) > best) w[c.k] = v;
🎯 완성 예제 기준 기본 가중치의 검증 AUC는 0.697, 자동 최적화 후 0.807입니다. 최적화 결과 "수습 일정 지연" 가중치는 0이 됩니다 — 직관적으로 중요해 보이는 요인이 실제로는 예측력이 없을 수 있다는 교훈입니다.

핵심 기술 ④ — 캐플런-마이어와 로그순위 검정

"평균 근속"은 재직 중인 사람을 버리지만, 생존 분석은 그 정보까지 씁니다
// 퇴사가 일어난 날마다 곡선을 계단식으로 내린다 let s = 1; times.forEach(t => { const n = rows.filter(r => r.t >= t).length; const d = rows.filter(r => r.e && r.t === t).length; s *= 1 - d / n; // 그날 버틴 비율을 곱한다 }); // t: 퇴사일 또는 오늘까지 재직일 // e: 퇴사 1 / 재직 중(관측 중단) 0
// 로그순위: 관측 퇴사(O) vs 기대 퇴사(E) times.forEach(t => { O += d1; E += d * n1 / n; V += d * (n1/n) * (1 - n1/n) * (n - d) / (n - 1); }); const chi = (O - E) ** 2 / V; const p = erfc(Math.sqrt(chi / 2)); // 자유도 1 카이제곱의 p값
📉 완성 예제 기준 180일 정착률은 멘토가 있던 입사자 82.3%, 없던 입사자 56.4%이고, 로그순위 검정 p < 0.001로 우연이 아닙니다. 이 근거로 "모든 입사자에게 멘토를 배정하자"는 정책을 제안할 수 있습니다.

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 계산을 시키는 법"을 배웁니다

POINT 1 — 그래프는 표로 준다

태스크 17개의 기간·담당·선행을 한 줄씩 적었습니다. "적당한 온보딩 절차"라고 하면 AI마다 다른 그래프를 만들어 결과를 비교할 수 없습니다.

POINT 2 — 경계 조건을 명시한다

"미완료 태스크는 오늘보다 먼저 끝날 수 없다"를 넣지 않으면, 일정대로인 사람도 지연으로 잡히는 버그가 생깁니다.

POINT 3 — 샘플 데이터도 설계한다

숨은 퇴사 함수의 계수까지 적었습니다. 데이터에 신호가 없으면 AUC가 0.5 근처로 나와 모델 수업이 성립하지 않습니다.

POINT 4 — 공정한 비교 조건

"재직자는 관측 중단", "45일 시점 점수로 180일 결과 예측"처럼 비교 기준을 정했습니다. 기준이 없으면 선택 편향이 섞인 그럴듯한 오답이 나옵니다.

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요
🔁 "순환 의존 오류가 나요"

태스크 선행 관계에 A→B→A 같은 고리가 있습니다. "위상 정렬 결과 개수가 태스크 수와 다른 태스크를 콘솔에 출력해줘"라고 요청하세요.

📅 "일정대로인데 전부 지연으로 나와요"

진행 중인 태스크를 오늘부터 새로 시작하는 것으로 계산한 버그입니다. 미완료 태스크는 EF = max(ES+기간, 오늘+1)로 고쳐 달라고 하세요.

🎯 "AUC가 0.5 근처예요"

샘플 데이터에 신호가 약한 경우입니다. 프롬프트의 숨은 퇴사 함수 계수를 그대로 쓰고, 퇴사자 수가 30명 이상인지 확인하세요.

📉 "정착 곡선이 1에서 안 내려가요"

퇴사 여부(e)와 기간(t)이 비었거나, 재직자를 빼 버린 경우입니다. 재직자도 오늘까지의 기간으로 포함해야 합니다.

🤖 만능 해결법: F12 → Console의 빨간 오류나 이상한 화면을 그대로 복사(캡처)해서 Antigravity에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요.
