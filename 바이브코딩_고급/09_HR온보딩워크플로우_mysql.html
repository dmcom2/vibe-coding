📌 상태 머신(State Machine)

온보딩이 정해진 단계(서류→환경설정→OJT…)를 순서대로 거치도록 진행률로 현재 상태를 판별하는 구조

📌 flatMap()

map으로 만든 2차원 배열을 flat(1)로 자동으로 펼쳐 1차원 배열로 만드는 배열 메서드

📌 체크리스트 배열

각 태스크를 {title, done} 형태 객체로 담은 배열. 체크박스 클릭 시 done 값만 토글

📌 진척률(%) 계산

완료 태스크 수 ÷ 전체 태스크 수 × 100. 진행률 바 너비(width)에 그대로 반영

📌 단계 전환 조건

진행률이 특정 % 구간(20/40/60/80/100)을 넘을 때마다 현재 단계 텍스트가 자동으로 바뀌는 분기 조건

📌 이중 localStorage

직원 정보와 태스크를 hrEmployees / hrTasks 두 개의 키로 나눠 저장하는 방식

핵심 기술 ① — flatMap() 태스크 자동 생성

템플릿에서 직원별 태스크를 한 번에 만드는 패턴
// 태스크 템플릿: 단계별 작업 정의 const TASK_TEMPLATE = [ { stage: 1, title: '입사 서류 제출', daysOffset: 0 }, { stage: 1, title: '사원증 발급 신청', daysOffset: 1 }, { stage: 2, title: 'PC 환경 설정', daysOffset: 3 }, { stage: 2, title: '사내 시스템 계정', daysOffset: 3 }, { stage: 3, title: '부서 OJT 시작', daysOffset: 7 }, { stage: 4, title: '1주차 보고서', daysOffset: 7 }, { stage: 5, title: '1개월 면담', daysOffset: 30 }, ]; // flatMap: 여러 직원 × 여러 태스크 → 1차원 배열로 function generateTasks(employees) { return employees.flatMap(emp => { const startDate = new Date(emp.joinDate); return TASK_TEMPLATE.map((tmpl, idx) => { const due = new Date(startDate); due.setDate(due.getDate() + tmpl.daysOffset); return { id: `${emp.id}_${idx}`, empId: emp.id, title: tmpl.title, stage: tmpl.stage, due: due.toISOString().slice(0, 10), done: false, }; }); }); }
💡 flatMap = map + flat(1). 각 직원마다 여러 태스크 배열이 생기는데, flatMap이 이를 자동으로 펼쳐서 하나의 1차원 배열로 만듭니다.

핵심 기술 ② — 진행률 & 단계 판별

완료 태스크 비율로 현재 단계 자동 계산
// 진행률 계산: 완료 수 / 전체 수 function getProgress(empId) { const empTasks = tasks.filter(t => t.empId === empId); if (empTasks.length === 0) return 0; const done = empTasks.filter(t => t.done).length; return Math.round(done / empTasks.length * 100); } // 진행률 % 구간으로 현재 단계 텍스트 결정 function getCurrentStage(pct) { if (pct >= 100) return { label: '온보딩 완료', color: '#10b981' }; if (pct >= 80) return { label: '마무리 단계', color: '#3b82f6' }; if (pct >= 60) return { label: 'OJT 진행 중', color: '#8b5cf6' }; if (pct >= 40) return { label: '환경 설정', color: '#f59e0b' }; if (pct >= 20) return { label: '서류 준비 중', color: '#f97316' }; return { label: '시작 전', color: '#64748b' }; } // 이중 localStorage 저장 function save() { localStorage.setItem('hrEmployees', JSON.stringify(employees)); localStorage.setItem('hrTasks', JSON.stringify(tasks)); }

직원 목록 & 태스크 패널

선택된 직원의 태스크를 오른쪽 패널에 표시하는 마스터-디테일 UI
1

직원 카드 클릭 → 태스크 패널

selectedEmpId = id 설정 후 오른쪽 패널에 해당 직원의 태스크 렌더링. 선택된 카드에 활성 스타일 적용.

2

진행률 바

getProgress(emp.id)로 % 계산 → width: ${pct}% 인라인 스타일로 프로그레스 바 너비 설정.

3

태스크 체크박스

체크 → task.done = !task.done → save() → renderAll(). 완료된 태스크는 선 긋기(text-decoration:line-through).

4

마감일 상태

오늘 대비 마감일이 지나면 빨간색, 3일 내면 주황, 여유 있으면 초록. daysLeft 계산.

5

신규 직원 추가

모달로 이름·부서·입사일 입력 → generateTasks([newEmp])로 태스크 자동 생성 후 배열에 concat.

단계별 스테이지 뷰

온보딩 5단계를 카드 레이아웃으로 시각화

스테이지 카드

TASK_TEMPLATE에서 stage별로 그룹핑. 각 스테이지 카드에 해당 태스크 목록과 완료율 표시. 100% 완료된 스테이지는 체크 뱃지.

전체 현황 통계

상단 대시보드에 전체 직원 수, 완료된 직원, 진행 중, 시작 전을 요약 카드로 표시. employees.map(getProgress)로 계산.

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 잘 말하는 법"을 배웁니다

POINT 1 — 외부 데이터 생애주기 명시

"fetch()로 CSV 로드, localStorage가 비었을 때 초기 데이터로 사용"처럼 데이터 흐름(외부 → 로컬 fallback)을 명시하면 AI가 조건 분기를 정확히 구현합니다.

POINT 2 — 엔터티 분리 스키마 지정

employees와 tasks를 별도 localStorage 키('hrEmployees'/'hrTasks')로 나누면 두 엔터티가 독립 CRUD 가능한 구조가 자동 생성됩니다. 스키마 분리 전략을 프롬프트에 명시했습니다.

POINT 3 — 레이아웃 픽셀 수치 직접 지정

"3열(좌측 280px, 우측 300px)"처럼 픽셀 값을 명시하면 CSS grid/flex 값이 정확하게 나와 레이아웃 수정 없이 바로 사용 가능한 코드가 생성됩니다.

POINT 4 — 드롭다운 옵션을 직접 열거

"부서(개발팀/마케팅팀/영업팀/인사팀/재무팀/기획팀/디자인팀)"처럼 select 옵션을 슬래시로 나열하면 실제 업무 데이터가 코드에 그대로 삽입됩니다.

미션 1: 온보딩 SLA 지연 모니터

각 온보딩 단계의 목표 완료 일수(SLA)를 상수로 정의하고, 입사일 기준 경과 일수가 SLA를 초과하면 직원 카드에 '지연 N일' 배지와 지연 단계명을 표시하는 모니터링 기능 구현.

  • 단계별 SLA 상수 객체 정의 (단계명 → 목표 완료 일수)
  • (today − startDate) 경과 일수 계산 로직 구현
  • SLA 초과 직원 카드에 '지연 N일' 배지 동적 렌더링

미션 2: 온보딩 병목 전환율 분석

각 단계에서 다음 단계로 넘어가는 데 걸린 평균 소요 일수와 현재 단계 체류 인원 비율을 계산해, 오른쪽 패널에 '단계 전환 분석' 섹션 추가. 가장 오래 걸리는 병목 단계를 색상으로 하이라이트.

  • 단계별 직원 수·체류 비율 집계 함수 작성
  • 단계 진입일 기준 평균 소요 일수 계산
  • 최대 소요 단계를 다른 색상으로 하이라이트 렌더링
