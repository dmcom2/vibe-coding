핵심 알고리즘 1 — 수요 예측 4모델

단순한 평균에서 계절성 분해까지, 모델마다 "무엇을 기억하는가"가 다릅니다
// 홀트-윈터스(승법): 수준 l · 추세 b · 계절 s for (let t = 12; t < n; t++) { const si = s[t - 12]; // 작년 같은 달 fit.push((l + b) * si); // 1-step 예측 const nl = α * y[t] / si + (1 - α) * (l + b); b = β * (nl - l) + (1 - β) * b; s.push(γ * y[t] / nl + (1 - γ) * si); l = nl; } // h개월 뒤 = (수준 + h·추세) × 계절지수
// 백테스트: 앞 18개월 학습 → 뒤 6개월 채점 function evaluate(sku, model, p) { const test = y.slice(18); const bt = FIT[model](y.slice(0, 18), p) .fc(test.length); const mape = mean(test.map((a, i) => Math.abs(bt[i] - a) / a)) * 100; return { mape, ... }; } // 파라미터는 학습구간 MSE 최소 그리드 서치 // → 검증 데이터를 훔쳐보지 않음(누수 방지)
📊 이동평균(최근 n개월 평균) · 단순 지수평활(α로 최근 가중) · 홀트 감쇠추세(추세를 점점 약하게) · 홀트-윈터스(계절까지). 완성 예제 기준으로 계절성이 강한 헤드셋은 홀트-윈터스 MAPE 19%, 이동평균 56% — 모델 선택이 곧 정확도입니다.

핵심 알고리즘 2 — 안전재고 · 재주문점 · EOQ

(s, Q) 정책: 재고 위치가 s(ROP) 이하가 되면 Q(EOQ)만큼 발주
// 서비스 수준 → z (역정규분포, Acklam 근사) const z = invNorm(sl / 100); // 95% → 1.645 // 리드타임 동안 수요의 표준편차 // 수요 변동 + 납기 변동을 함께 반영 const sLT = Math.sqrt(L * sd * sd + d * d * sL * sL); const ss = z * sLT; // 안전재고 const rop = d * L + ss; // 재주문점
// EOQ: 발주비 = 보관비가 되는 주문량 const eoq = Math.sqrt(2 * D * S / H); // 충족률(Fill rate): 손실함수 G(z) 사용 const G = z => pdf(z) - z * (1 - cdf(z)); const fill = 1 - sLT * G(z) / eoq; // 서비스 수준(CSL): 주기당 품절 안 날 확률 // 충족률: 주문 수량 중 즉시 출고 비율
🔢 서비스 수준을 95% → 99%로 올리면 z가 1.645 → 2.326으로 커져 안전재고가 약 41% 증가합니다. 99.9%에서는 곡선이 급격히 치솟습니다 — 앱의 "서비스 수준 ↔ 안전재고" 차트로 직접 확인하세요.

핵심 알고리즘 3 — 몬테카를로 시뮬레이션

수식은 평균을 말하고, 시뮬레이션은 분포를 말합니다
// 하루 단위로 180일 가상 운영 (1회) for (let t = 0; t < days; t++) { receive(pipe, t); // 도착한 주문 입고 const q = mu + sd * gauss(rng); // 무작위 수요 const s = Math.min(on, q); // 출고 if (q > s) lost += q - s; // 품절 → 판매 손실 if (on + onOrder <= rop) // 재주문점 도달 pipe.push({ day: t + randomLT(), q: eoq }); }
// 500회 반복 → 일자별 분위수 for (let t = 0; t < days; t++) { const col = paths.map(r => r[t]) .sort((a, b) => a - b); p5.push(q(col, .05)); p50.push(q(col, .5)); p95.push(q(col, .95)); } // 공통 난수(시드 고정) → 시나리오 공정 비교 // setTimeout 청크 실행 → 화면 멈춤 방지
🎲 시나리오 4종 — 기준 / 수요 급증(+30%) / 공급 지연(리드타임 ×1.8, 변동 ×2) / 프로모션(60~90일차 2배). 같은 정책도 공급 지연에서는 주기당 품절이 수십 %까지 오릅니다. 정책은 "평소"가 아니라 "나쁜 날" 기준으로 점검하세요.
실무 시나리오 — 왜 이 도구가 필요한가
재고 과잉과 품절, 두 위험을 숫자로 관리한다
문제 1 — 감으로 하는 발주
"작년 이맘때 이 정도 팔렸으니…" 담당자 경험에 의존한 발주는 성수기 품절, 비수기 과잉을 반복합니다. 백테스트로 검증된 모델이 기준이 되어야 합니다.
문제 2 — 모든 품목을 똑같이
매출 50%를 차지하는 노트북과 케이블을 같은 기준으로 관리하면 비효율적입니다. ABC–XYZ 등급에 따라 서비스 수준과 관리 강도를 달리합니다.
해결 — 싸고 느린 공급자?
단가 10% 저렴한 해외 공급자는 리드타임이 길고 불안정해 안전재고가 늘어납니다. 스코어카드와 총비용(구매+운영) 비교로 판단합니다.
검증 — 실행 전에 미리 겪어보기
새 정책을 바로 적용하지 않고 몬테카를로로 수백 번 가상 운영합니다. 공급 지연·프로모션 같은 나쁜 날의 품절 확률을 먼저 확인합니다.
"모든 모델은 틀렸다. 그러나 일부는 쓸모가 있다." — George Box

데이터 구조 설계

품목 하나에 예측 결과와 정책이 차례로 붙는 구조 — analyze(sku)가 전체를 다시 계산

품목 SKU

{ code, name, hist[24], unitCost, price, lt, S, h, onHand, po }
hist는 시드 고정 난수로 만든 24개월 판매량. po는 입고 예정 주문 {qty, eta}.

공급자 SUPPLIERS

{ name, ltMul, ltCv, cost, quality, otd }
리드타임 = 기준 lt × ltMul, 표준편차 = 리드타임 × ltCv. cost는 단가 배수.

예측 결과 sku.evals[model]

{ fit[], bt[], fc[6], mape, mae, rmse, bias, sigma }
sigma(잔차 표준편차)가 예측 구간과 안전재고 계산의 재료가 됩니다.

정책 sku.pol

{ z, d, sd, L, sL, ss, rop, eoq, fill, total }
policy(sku, {sl, sup})로 다른 조건을 가정한 "what-if" 계산도 같은 함수로 처리합니다.

폴더 열기

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요

📈 "차트가 아예 안 나와요"

Chart.js CDN은 인터넷 연결이 필요합니다. F12 → Console의 빨간 오류를 복사해 Antigravity에게 붙여넣으세요.

🐢 "시뮬레이션 중 화면이 멈춰요"

반복 횟수를 200회로 줄여 보세요. "시뮬레이션을 40회씩 나눠 setTimeout으로 실행하고 진행 막대를 보여줘"라고 요청하면 해결됩니다.

🌀 "홀트-윈터스 예측이 이상해요"

계절 모델은 최소 12개월 이상으로 계절지수를 초기화해야 합니다. 예측이 음수라면 Math.max(0, …) 처리를 요청하세요.

🎚️ "슬라이더를 끌면 손에서 놓쳐요"

드래그 중에 슬라이더 HTML을 다시 그리면 생깁니다. "슬라이더는 다시 만들지 말고 값만 갱신해줘"라고 요청하세요.

🤖 만능 해결법: 오류 메시지나 이상한 화면을 그대로 복사(캡처)해서 Antigravity에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요.
