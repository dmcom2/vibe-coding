계층 구조

Objective (목표) → Key Results 3개 → 진행률(%) 3단계 계층. 상위 Objective 진행률은 하위 KR 평균으로 자동 계산.

상태 자동 판별

KR 평균이 70% 이상 → on-track, 40% 이상 → at-risk, 미만 → behind. 배지 색상으로 즉시 시각화.

📌 Objective / Key Result

핵심 개념 ① — 계층형 데이터 구조

Objective → Key Results 3계층을 배열로 표현하는 방법
// OKR 데이터 구조: Objective 안에 keyResults 배열 const okrData = [ { id: 1, objective: '고객 만족도 1위 달성', team: '고객팀', keyResults: [ { id: '1-1', kr: 'NPS 점수 70점 달성', progress: 65, target: 70 }, { id: '1-2', kr: 'CS 응답시간 1시간 이내', progress: 80, target: 100 }, { id: '1-3', kr: '리텐션율 85% 달성', progress: 45, target: 85 }, ] } ]; // Objective 진행률 = KR 평균 function getObjProgress(obj) { const avg = obj.keyResults.reduce((sum, kr) => sum + kr.progress, 0) / obj.keyResults.length; return Math.round(avg); }
💡 중첩 배열 구조로 계층적 데이터를 표현. keyResults는 Objective 객체 안에 배열로 포함되어 부모-자식 관계를 코드로 명확히 표현합니다.

핵심 개념 ② — 상태 자동 계산

진행률 숫자 → 의미 있는 상태 배지로 변환
// 진행률 → 상태 자동 판별 function getStatus(progress) { if (progress >= 70) return { label: 'on-track', color: '#10b981' }; if (progress >= 40) return { label: 'at-risk', color: '#f59e0b' }; return { label: 'behind', color: '#6366f1' }; } // 진행률 바 색상도 동일 함수로 통일 function renderProgressBar(progress) { const status = getStatus(progress); return `<div class="progress-bar"> <div style="width:${progress}%;background:${status.color}"></div> </div>`; } // 배지 렌더링 function renderBadge(progress) { const status = getStatus(progress); return `<span class="badge" style="background:${status.color}20;color:${status.color}"> ${status.label} </span>`; }
on-track ≥70% at-risk ≥40% behind <40%

핵심 개념 ③ — localStorage CRUD

Create · Read · Update · Delete 전체 흐름을 한 패턴으로
// ── 초기 로드 ────────────────────── let okrData = JSON.parse( localStorage.getItem('okrData') || 'null' ) || defaultOkrData; // null이면 기본값 사용 // ── 저장 (Create·Update·Delete 후 공통 호출) ── function save() { localStorage.setItem('okrData', JSON.stringify(okrData)); } // ── Update — KR 진행률 수정 ────────── function updateProgress(objId, krId, value) { const obj = okrData.find(o => o.id === objId); const kr = obj.keyResults.find(k => k.id === krId); kr.progress = parseInt(value); save(); render(); // UI 전체 갱신 } // ── Delete — Objective 삭제 ───────── function deleteObj(objId) { okrData = okrData.filter(o => o.id !== objId); save(); render(); }
💡 save() → render() 패턴을 모든 데이터 변경 함수에 통일 적용. 데이터와 UI가 항상 동기화됩니다.

도넛 차트 실시간 갱신

슬라이더 조작 시 차트가 즉시 반응하는 패턴
1

초기 차트 생성

도넛 차트 datasets에 각 Objective의 진행률 배열을 주입. cutout: '70%'로 중앙 구멍 크기 설정.

2

데이터 업데이트

슬라이더 oninput 이벤트 → updateProgress() 호출 → chart.data.datasets[0].data 배열 수정.

3

chart.update() 호출

destroy/재생성 없이 chart.update() 한 줄로 애니메이션과 함께 차트 갱신. 기존 인스턴스 유지.

4

중앙 텍스트 갱신

Chart.js 플러그인 없이 canvas 위에 절대 위치 div를 얹어 전체 평균 퍼센트를 표시. CSS pointer-events:none으로 클릭 통과.

중첩 데이터 렌더링

Objective → Key Results 2중 루프 HTML 생성
function render() { document.getElementById('okrList').innerHTML = okrData.map(obj => { const progress = getObjProgress(obj); const status = getStatus(progress); // 내부 KR 행들 생성 (2중 루프) const krRows = obj.keyResults.map(kr => ` <div class="kr-row"> <span>${kr.kr}</span> <input type="range" min="0" max="100" value="${kr.progress}" oninput="updateProgress(${obj.id},'${kr.id}',this.value)"> <span>${kr.progress}%</span> </div> `).join(''); return `<div class="obj-card"> <div class="obj-header"> ${obj.objective} <span style="color:${status.color}">${progress}%</span> </div> <div class="kr-list">${krRows}</div> </div>`; }).join(''); }
💡 외부 .map(obj => ...)에서 내부 .map(kr => ...)을 템플릿 리터럴 안에 중첩. 계층 구조를 코드 들여쓰기로 시각화.

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 잘 말하는 법"을 배웁니다

POINT 1 — 계층 구조를 글로 표현

"Objective에 KR 여러 개 (동적 추가/삭제)"처럼 중첩 데이터 모델을 자연어로 명시하면 AI가 올바른 배열 구조를 설계합니다.

"on-track(70% 이상)/at-risk(40~69%)/behind(40% 미만)"처럼 상태 판별 기준을 숫자로 직접 정의하면 AI가 정확한 조건문을 작성합니다.

"슬라이더+숫자 직접 입력 연동"처럼 두 UI 요소가 서로 동기화돼야 함을 서술하면 AI가 양방향 이벤트 핸들러를 구현합니다.

상태 필터 칩과 진행률 필터 칩을 각각 열거하면 AI가 두 조건을 AND로 결합하는 복합 필터 로직을 설계합니다.
