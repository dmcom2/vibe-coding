오늘 나오는 용어 미리보기

외우지 마세요 — 눈에만 익혀 두면 수업이 술술 풀립니다

📌 목표 · 핵심 결과(KR)

목표는 가고 싶은 방향(정성), KR은 도착했는지 재는 숫자. "대기업 고객을 빠르게 늘린다" / "신규 대기업 계약 0 → 60건".

📌 약속 · 도전 목표

약속은 100% 달성해야 하는 목표, 도전은 70%만 가도 성공인 목표. 기대 진척도 도전 목표는 × 0.7로 봅니다.

📌 체크인 · 자신감

매주 KR의 현재 값과 "분기 말까지 해낼 수 있다"는 느낌을 1~10으로 기록. 숫자보다 먼저 위험을 알려 주는 신호입니다.

📌 기대 진척

기준일까지 분기가 흐른 비율. 8/26이면 7/1~9/30 중 62% — KR도 그만큼은 와 있어야 순조입니다.

📌 정렬 (Alignment)

팀 목표가 어떤 상위 목표에 기여하는지 연결하는 것. 연결이 없으면 "왜 이걸 하지?"에 답할 수 없습니다.

📌 관계형 DB · 외래키

목표 1개에 KR 여러 개, KR 1개에 체크인 여러 개. 외래키로 이어 두면 목표를 지울 때 KR · 체크인도 함께 지워집니다(연쇄 삭제).

핵심 기술 ① — 관계형 SQLite: 목표 · KR · 체크인

1 : N : N 관계를 테이블 3개와 외래키로 — 지우면 같이 지워지고, 같은 날 체크인은 덮어쓴다
db.pragma('foreign_keys = ON'); CREATE TABLE objectives (id TEXT PRIMARY KEY, team, owner, title, parent REFERENCES objectives(id) ON DELETE SET NULL, type); CREATE TABLE krs (id TEXT PRIMARY KEY, obj REFERENCES objectives(id) ON DELETE CASCADE, title, unit, start, target, dec, weight, current); CREATE TABLE checkins (id INTEGER PRIMARY KEY, kr REFERENCES krs(id) ON DELETE CASCADE, date, value, confidence, comment, UNIQUE (kr, date));
// 체크인: 같은 KR · 같은 날이면 덮어쓰기 (UPSERT) app.post('/api/checkins', (req, res) => { db.transaction(() => { db.prepare(`INSERT INTO checkins (kr,date,value,confidence,comment) VALUES (?,?,?,?,?) ON CONFLICT(kr,date) DO UPDATE SET value=excluded.value, …`).run(…); // KR의 현재값 = 가장 최근 체크인 db.prepare('UPDATE krs SET current=? WHERE id=?').run(last, kr); })(); });
🗄️ 완성 예제 기준 서버를 처음 켜면 목표 8개 · KR 24개 · 체크인 186건(7/3부터 매주 금요일)이 들어갑니다. 목표를 지우면 그 KR과 체크인이 연쇄 삭제되고, 하위 목표는 상위 연결만 풀려 최상위가 됩니다.

핵심 기술 ② — 측정형 진척과 상태 자동 판정

진척은 공식 하나, 상태는 "기대 진척과의 거리 + 자신감"
// 줄여야 하는 지표도 같은 식 (목표 < 시작이면 분모가 음수) const progress = kr => (kr.current - kr.start) / (kr.target - kr.start); // 0 ~ 1.2 // 기대 진척 = 분기 경과율 (도전 목표는 × 0.7) const e = (기준일 - 분기 시작) / (분기 끝 - 분기 시작); const exp = type === 'aspirational' ? e * 0.7 : e; // 목표 진척 = KR 진척(최대 1)의 비중 가중 평균
function status(p, exp, conf) { let s = p >= exp - 0.15 ? '순조' : p >= exp - 0.30 ? '주의' : '위험'; if (conf <= 2) s = '위험'; // 스스로 포기 신호 else if (conf <= 4 && s === '순조') s = '주의'; return s; }
📏 완성 예제 기준(기준일 8/26) 분기 경과 62%, 전체 진척 42%(기대보다 −15%p), KR 상태 순조 11 · 주의 8 · 위험 5. 월 이탈률(3.0 → 1.8%)이 지금 2.52%면 진척 40%, 배포 주기(14 → 7일)가 12.6일이면 20%로 위험입니다.

핵심 기술 ③ — 주간 체크인과 분기 말 예측

최근 4번의 체크인 속도로 분기 마지막 날을 내다보고, 밀린 체크인은 따로 챙긴다
// 최근 체크인 4번의 (날짜, 진척)에 직선을 맞춰 분기 끝 값 function forecast(kr, cks) { const pts = cks.slice(-4).map(c => [toDay(c.date), progress(kr, c.value)]); const b = 기울기(pts); // 최소제곱 return clamp(평균p + b * (분기끝 - 평균날짜), 0, 1.3); } // 처음부터 전부 쓰면 초반 급성장에 끌려 150%처럼 과대 예측
// 체크인 필요: 마지막 체크인이 기준일보다 7일 넘게 전 stale = !last || (기준일 - last.date) > 7; // 체크인 화면: 입력하는 순간 미리보기 `→ 진척 ${새 진척} (기대 ${exp}) · ${새 상태} 예상` // 분석: 금요일마다 그날 기준으로 analyze()를 다시 돌려 // 팀별 진척 추이 · 자신감 히트맵을 그린다
⏱️ 완성 예제 기준 HR팀 KR 3개는 8/7 이후 체크인이 없어 체크인 필요 3개입니다. '핵심 인재 채용'에 6명(자신감 7)을 기록하면 진척 25% → 50%, 상태가 순조로 바뀌고 체크인 필요가 2개로 줄어듭니다. 전체 분기 말 예상은 69%입니다.

핵심 기술 ④ — 정렬 맵과 롤업

부모-자식 관계를 트리로 배치 — 하위 트리의 폭을 먼저 재고 부모를 가운데에 놓는다
// 하위 트리 폭: 자식이 없으면 카드 폭 const width = o => { const ch = kids(o.id); return ch.length ? sum(ch.map(width)) + 간격 : 220; }; const place = (o, x, depth) => { pos[o.id] = { x: x + width(o) / 2 - 110, y: depth * 188 }; let cx = x; kids(o.id).forEach(c => { place(c, cx, depth + 1); cx += width(c) + 간격; }); }; // 연결선: 부모 아래 → 중간 높이 → 자식 위 (꺾은선)
// 롤업: 하위 목표 포함 진척 = (내 진척 + 자식 진척들) 평균 v.rollup = (v.p + sum(자식 진척)) / (자식 수 + 1); // 순환 방지: 새 상위를 따라 올라가다 나를 만나면 거절 function makesCycle(id, parent) { for (let p = parent; p; p = objOf(p).parent) if (p === id) return true; return false; }

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 운영 시스템을 시키는 법"을 배웁니다

POINT 1 — 관계를 먼저 그린다

"목표 1 : KR N : 체크인 N, 삭제 시 연쇄"를 테이블 정의로 적으면, 삭제 · 수정 기능이 저절로 일관되게 만들어집니다.

POINT 2 — 판정 규칙을 숫자로

"잘 되고 있는지 표시해줘" 대신 기대 − 0.15 / − 0.30, 자신감 2 · 4 같은 경계값을 줬습니다. 팀마다 다른 해석이 끼어들 틈이 없습니다.

POINT 3 — 좋은 OKR의 조건을 규칙으로

"잘 쓴 OKR인지 봐줘"는 막연합니다. 과제형 어미 · 비중 합 · 목표 속 숫자 · 정렬처럼 검사할 수 있는 규칙으로 바꿨습니다.

POINT 4 — 같은 규칙을 한 파일에

서버 보고서 · 화면 · CSV 미리보기가 모두 data.js를 쓰게 해서, "보고서와 화면 숫자가 달라요" 문제를 원천 차단했습니다.

서버 실행 방법

터미널 두 줄이면 SQLite 서버가 켜집니다 — 안 되면 index.html만 열어도 로컬 데모 모드
1

설치 · 실행

실습 폴더에서 npm install → npm start. "샘플 OKR: 목표 8개 · KR 24개 · 체크인 186건"과 주소가 보이면 성공입니다.

2

http://localhost:3001 열기

배지가 초록 '서버 · SQLite'인지 확인하고, 개요에서 지금 챙겨야 할 KR을 봅니다.

3

체크인 · 정렬

4번 체크인에서 '핵심 인재 채용'에 6명 · 자신감 7을 기록하고, 2번 정렬 맵에서 점선 테두리 목표를 찾아 상위를 연결해 보세요.

4

초안 가져오기 · 보고서

가져오기로 샘플 CSV의 품질 지적 6건을 확인하고, 보고서를 눌러 인쇄(Ctrl+P)해 봅니다. 끝낼 때는 터미널에서 Ctrl+C.

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요
🔗 "FOREIGN KEY constraint failed"

없는 목표 id로 KR을 만들거나, 상위 목표를 먼저 지운 경우입니다. 샘플을 넣을 때는 "목표를 모두 넣은 뒤 상위 연결을 UPDATE"하는 순서를 요청하세요.

📉 "줄여야 하는 KR의 진척이 음수예요"

(현재 − 시작) ÷ (목표 − 시작) 대신 현재 ÷ 목표로 계산했을 가능성이 큽니다. 공식을 그대로 붙여넣고 0 ~ 1.2로 자르게 하세요.

🚪 "3001 포트 사용 중"

다른 서버가 3001을 쓰고 있습니다. 그 터미널을 Ctrl+C로 끄거나 $env:PORT=3101; npm start(PowerShell)로 바꿔 여세요.

🖨️ "보고서 버튼을 눌러도 안 열려요"

브라우저가 새 창(팝업)을 막았습니다. 주소창 오른쪽의 팝업 차단 아이콘에서 허용한 뒤 다시 누르세요.

🤖 만능 해결법: 터미널의 빨간 글자나 F12 → Console의 오류를 그대로 복사해서 Antigravity에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요.

AI 프롬프트 요령 & 실습 미션

운영 · 관리 시스템을 AI에게 맡길 때의 요령과 확장 과제
1

"기준 날짜"를 고정한다

'오늘'로 판정하면 실습 날마다 결과가 바뀝니다. 기준일을 설정값으로 두면 과거 시점도 다시 볼 수 있습니다.

2

경고는 막지 말고 알려 준다

품질 점검은 저장을 막지 않고 저장 후 권고로 두었습니다. 규칙이 너무 딱딱하면 사람들이 시스템을 피해 갑니다.

3

미션 1: 체크인 알림

체크인이 7일 넘게 밀린 담당자 목록을 뽑아 메일 본문(누구 · 어떤 KR · 며칠)을 만들어 주는 버튼을 추가합니다.

4

미션 2: 분기 마감 · 이월
