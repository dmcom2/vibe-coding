📌 다면평가 가중치

자기 15 · 상사 40 · 동료 30 · 부하 15. 없는 유형은 빼고 나머지 가중치를 다시 나눠 종합 점수를 냅니다.

📌 관대화·엄격화

누구에게나 후하게(또는 박하게) 주는 평가자 성향. 같은 사람을 본 다른 평가자 평균과의 차이로 추정합니다.

📌 수축 추정

평가를 3건만 한 사람의 성향은 믿기 어렵습니다. n/(n+3)을 곱해 건수가 적을수록 0에 가깝게 줄입니다.

📌 후광 효과

한 가지 인상으로 모든 역량에 비슷한 점수를 주는 경향. 한 평가 안의 역량 간 표준편차가 매우 작으면 의심합니다.

📌 크론바흐 α

6개 역량 점수가 함께 움직이는 정도(내적 일관성). 0.7 이상이면 쓸 만하고, 0.95를 넘으면 역량 구분이 안 되는 것.

📌 익명성 기준 · 스냅숏

동료·부하 응답이 3명 미만이면 그룹 점수·코멘트 출처를 숨깁니다. 스냅숏은 확정 순간의 등급을 복사해 두어 이후 계산이 바뀌어도 결과가 흔들리지 않게 합니다.

핵심 기술 ① — 유형별 가중 평균으로 종합 점수

빠진 유형이 있어도 공정하게: 있는 유형의 가중치만 다시 나눈다
// 가중치: 자기 15 · 상사 40 · 동료 30 · 부하 15 function wavg(parts) { // [[유형, 값], …] const p = parts.filter(([, v]) => v != null); const ws = sum(p.map(([t]) => W[t])); return sum(p.map(([t, v]) => W[t] * v)) / ws; } // 사원은 부하평가가 없으므로 // 자기 15 · 상사 40 · 동료 30 → 85로 나눔
// 타인 평가 = 상사·동료·부하만 p.others = COMPS.map((_, c) => wavg(['boss', 'peer', 'report'] .map(k => [k, p.t[k]?.[c]]))); // 종합 = 자기평가까지 네 유형 p.overall = wavg(TYPES.map(({ k }) => [k, p.t[k] ? mean(p.t[k]) : null]));
🪞 완성 예제 기준 개발팀 황지호 과장은 자기평가 4.33, 타인 평가 2.85로 차이가 +1.48입니다. 6개 역량 중 5개가 '맹점'이라 개인 개발 계획은 성과 달성(1.96)과 협업·팀워크(2.54)를 1·2순위로 추천합니다.

핵심 기술 ② — 평가자 관대화 보정 (수축 추정)

"다른 사람들은 3점을 줬는데 이 평가자만 늘 4점"을 숫자로 잡아낸다
// 평가 1건: 내 점수 − 다른 평가자 평균 const dev = mean(r.s.map((v, c) => v - (a.sum[c] - v) / (a.n - 1))); // 평가자별로 모아 평균 x.L = mean(x.devs); x.Lh = x.L * x.n / (x.n + 3); // 수축 x.flag = x.Lh >= 0.4 ? '관대' : x.Lh <= -0.4 ? '엄격' : null;
// 보정 점수 = 점수 − 성향 (1~5로 제한) const adj = r => r.type === 'self' ? r.s // 자기평가는 제외 : r.s.map(v => clamp(v - raters.get(r.rater).Lh, 1, 5)); // 후광: 한 평가 안 역량 간 표준편차 평균 < 0.3 x.halo = x.n >= 3 && mean(x.sds) < 0.3;
⚖️ 완성 예제 기준 관대 2명(송수빈 +0.54, 신준서 +0.43), 엄격 4명, 후광 3명이 잡힙니다. 보정을 켜면 48명 중 36명의 순위가 바뀌고, 가장 크게는 36위 → 43위까지 움직입니다.

핵심 기술 ③ — 크론바흐 α로 측정 신뢰도 점검

6개 역량 점수가 "같은 것을 일관되게" 재고 있는지 한 숫자로
// rows: 제출된 평가들의 [역량 6개 점수] function alpha(rows) { const k = 6; const items = COMPS.map((_, c) => variance(rows.map(r => r[c]))); const tot = variance(rows.map(r => sum(r))); return k / (k - 1) * (1 - sum(items) / tot); } // variance는 표본 분산 (n − 1로 나눔)
// 해석 기준 if (a >= 0.95) '후광 의심' // 너무 똑같이 움직임 else if (a >= 0.8) '높음' else if (a >= 0.7) '수용' else '낮음' // 문항 점검 필요 // 전체와 평가 유형별로 따로 계산해 // 어느 평가자 집단이 흔들리는지 본다
📏 완성 예제 기준 전체 α는 0.82(높음)입니다. 유형별로는 자기 0.86 · 상사 0.79 · 동료 0.84 · 부하 0.70 — 부하평가는 겨우 수용 수준이라, 부하 평가 문항 안내를 더 구체적으로 할 필요가 있습니다.

핵심 기술 ④ — 9-Box와 강제 배분 등급

같은 점수라도 "어떻게 자르느냐"에 따라 결과가 달라진다

"누가 썼는지 드러나지 않게", "확정된 결과는 흔들리지 않게" — 운영 시스템의 두 가지 약속

🔒 완성 예제 기준 동료·부하 응답이 3명 미만이라 리포트에서 그룹이 비공개되는 직원은 26명입니다. 보정 검토 단계에서 황지호 과장을 사유와 함께 C → B로 조정하면 배분 검증표에 B +1 · C −1이 표시되고, 확정 후에는 가중치를 바꿔도 최종 등급이 그대로 유지됩니다.

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 공정성 로직을 시키는 법"을 배웁니다

POINT 1 — 정답이 있는 가짜 데이터

관대·엄격·후광 평가자와 맹점 직원을 일부러 심었습니다. 보정 기능이 그들을 실제로 찾아내는지 검증할 수 있는 데이터가 됩니다.

POINT 2 — 공식과 기준값을 모두 적는다

"편향을 보정해줘"만 쓰면 AI가 평균 차이·z점수·백분위 등 제각각입니다. 편차 정의, 수축 n/(n+3), ±0.4 기준까지 적었습니다.

POINT 3 — 예외를 먼저 정한다

"자기평가·익명은 보정 제외", "없는 유형은 가중치를 다시 나눔"처럼 빈칸 처리 규칙을 적어야 사원·신규 입력 직원에서 오류가 안 납니다.

POINT 4 — 상태와 잠금을 설계한다

"마감 후 입력 금지", "확정은 스냅숏", "조정에는 사유"처럼 단계별로 무엇이 가능하고 무엇이 잠기는지 적었습니다. 운영 도구는 계산보다 이 규칙이 신뢰를 좌우합니다.

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요
🧮 "사원 종합 점수가 이상하게 낮아요"

부하평가가 없는데 0점으로 계산했거나 가중치를 다시 나누지 않은 경우입니다. "없는 유형은 빼고 남은 가중치 합으로 나눠줘"라고 요청하세요.

⚖️ "보정했더니 점수가 5를 넘어요"

엄격한 평가자의 점수에서 음수 성향을 빼면 5를 넘을 수 있습니다. "보정 점수는 1~5로 제한해줘"를 추가하세요.

🔢 "평가자가 누구나 관대/엄격으로 떠요"

평가 2~3건만 한 평가자는 우연히 튀기 쉽습니다. 수축 계수 n/(n+3)이 빠졌는지 확인하세요.

🔓 "확정했는데 가중치를 바꾸니 등급이 바뀌어요"

확정 등급을 계산식으로 다시 구하고 있기 때문입니다. "확정 순간의 직원별 등급을 스냅숏으로 저장하고, 최종 등급은 스냅숏을 먼저 쓰게 해줘"라고 요청하세요.

🤖 만능 해결법: F12 → Console의 빨간 오류나 이상한 화면을 그대로 복사(캡처)해서 Antigravity에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요.
