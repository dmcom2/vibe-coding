핵심 기술 ① — 가중 매출 & KPI

확률을 반영한 현실적인 매출 예측
// 딜 데이터 구조 const STAGES = [ { id: 1, name: '리드', prob: 10 }, { id: 2, name: '제안', prob: 30 }, { id: 3, name: '협상', prob: 60 }, { id: 4, name: '계약', prob: 90 }, { id: 5, name: '완료', prob: 100 }, ]; // 가중 매출: 금액 × 확률/100 function calcWeightedRev(deals) { return deals.reduce((sum, d) => { const prob = STAGES.find(s => s.id === d.stage)?.prob || 0; return sum + d.amount * prob / 100; }, 0); } // Win Rate: 완료 딜 수 / 전체 딜 수 function calcWinRate(deals) { if (deals.length === 0) return 0; const won = deals.filter(d => d.stage === 5).length; return Math.round(won / deals.length * 100); } // 평균 딜 사이즈 const avgDeal = deals.reduce((s, d) => s + d.amount, 0) / deals.length;
💡 단순 합계가 아닌 확률 가중치를 적용한 예상 매출이 파이프라인 관리의 핵심입니다. "계약 단계 딜은 90% 확률이니 90%만 집계"

칸반 보드 렌더링

각 스테이지 컬럼에 딜 카드를 동적으로 배치
1

컬럼 헤더

스테이지별 딜 수와 합계 금액을 헤더에 표시. deals.filter(d => d.stage === stageId)로 해당 컬럼의 딜 목록 추출.

2

딜 카드

고객명, 담당자, 금액, 확률, 예상 마감일 표시. 카드 상단에 스테이지 확률 뱃지(prob%). 금액은 toLocaleString()으로 천 단위 구분.

3

단계 이동 버튼

카드 하단에 ← (이전) / → (다음) 버튼. deal.stage = Math.min/max(1~5, stage±1) 후 save() + renderAll().

4

금액 수정

금액 클릭 시 인라인 input으로 전환. 포커스 아웃 시 숫자로 파싱 후 저장. contenteditable 또는 inline edit 패턴.

5

컬럼 색상

각 스테이지별 고유 색상(파랑→주황→초록→골드→emerald). 딜 카드 헤더 좌측 보더 색상으로 구분.

리스트 뷰 & 담당자 실적

표 형태와 담당자별 집계 분석

리스트 뷰 테이블

전체 딜을 테이블로 표시. 컬럼: 고객사, 담당자, 금액, 단계, 확률, 가중매출, 마감일. 클릭 시 상세 모달 또는 칸반 이동.

담당자별 집계

deals.reduce로 담당자별 딜 수·합계·가중매출 집계. repStats 객체를 만들어 차트와 테이블에 공통 사용.

// 담당자별 실적 집계 function calcRepStats() { const stats = {}; deals.forEach(d => { if (!stats[d.rep]) stats[d.rep] = { count: 0, total: 0, weighted: 0 }; const s = stats[d.rep]; s.count++; s.total += d.amount; const prob = STAGES.find(st => st.id===d.stage)?.prob || 0; s.weighted += d.amount * prob / 100; }); return stats; }

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 잘 말하는 법"을 배웁니다

POINT 1 — 데이터 스키마 명시

딜 데이터 구조 {id, company, amount, prob, stage, owner ...}를 직접 나열해 AI가 필드명과 타입을 추측하지 않도록 고정. 잘못된 변수명으로 생기는 버그를 원천 차단.

POINT 2 — 비즈니스 공식 직접 제시

"가중 매출 = amount × prob/100"을 수식으로 명시. "가중 매출을 계산해줘"처럼 추상적으로 말하면 AI마다 공식이 달라짐. 핵심 로직은 반드시 공식으로 써줄 것.

POINT 3 — 차트 메모리 관리 패턴 지정

"charts{} 객체로 관리, destroy() 후 재생성"이라고 구현 패턴까지 요청. 이 패턴 없이 차트를 재렌더링하면 메모리 누수가 발생. AI에게 패턴 이름을 알려주면 정확히 적용.

POINT 4 — 파일 분리와 출력 형식 명시

"index.html · style.css · script.js 3개로 나눠서"라고 출력 파일 구조를 지시. 명시하지 않으면 AI는 모든 코드를 한 파일에 담음. 원하는 파일 구조는 항상 명시.
