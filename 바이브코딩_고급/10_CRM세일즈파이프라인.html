📌 로지스틱 회귀

여러 조건을 점수로 더한 뒤 sigmoid로 0~1 확률로 바꾸는 모델. "수주할까, 실주할까"처럼 둘 중 하나를 예측할 때 씁니다.

📌 오즈 · 계수 β

오즈 = 성공확률 ÷ 실패확률. 계수 β가 0.84면 해당 조건이 1단계 늘 때 오즈가 e^0.84 ≈ 2.3배가 됩니다.

📌 AUC · ROC

수주 딜과 실주 딜을 무작위로 하나씩 골랐을 때 모델이 수주 딜에 더 높은 점수를 줄 확률. 0.5는 동전 던지기, 1.0은 완벽.

📌 정밀도 · 재현율

정밀도: "수주할 것"이라 한 딜 중 실제 수주 비율. 재현율: 실제 수주 딜 중 맞힌 비율. 임계값으로 균형을 조절합니다.

📌 슬립(Slip)

이번 기간에 닫힐 줄 알았던 딜이 다음 기간으로 밀리는 것. 활동 공백이 길고 마감일이 지난 딜일수록 슬립 확률이 큽니다.

📌 판매 속도

진행 딜 수 × 평균 딜 규모 × 승률 ÷ 판매 주기. 하루에 파이프라인이 매출로 바뀌는 속도(원/일)입니다.

핵심 기술 ① — 로지스틱 회귀를 브라우저에서 학습

라이브러리 없이 경사하강법 30줄로 "무엇이 수주를 만드는가"를 데이터에서 찾아냅니다
// 딜 → 숫자 8개 (단계는 결과를 누설하므로 제외) function rawFeats(d, asOf) { return { dm: d.dm ? 1 : 0, // 의사결정자 접촉 comp: d.competitor ? 1 : 0, acts: /* 최근 30일 활동 수 */, gap: /* 마지막 활동 경과일 */, size: Math.log10(d.amount), ref, inb, outb // 리드 소스 원-핫 }; } // 학습 70% · 검증 30%, 학습 평균·표준편차로 표준화
// 배치 경사하강법 + L2 정규화 for (const r of train) { const p = sigmoid(b + dot(w, r.z)); const err = p - r.y; // 예측 − 정답 gb += err; r.z.forEach((v, j) => gw[j] += err * v); } for (let j = 0; j < k; j++) w[j] -= lr * (gw[j] / n + λ * w[j]); b -= lr * gb / n; // 600회 반복 → 학습·검증 손실 곡선 기록
📉 앱의 모델 재학습 버튼을 누르면 손실 곡선이 실시간으로 그려집니다. 학습 손실만 내려가고 검증 손실이 벌어지면 과적합 — λ를 올려 계수를 눌러 주세요.

핵심 기술 ② — 모델 평가: AUC와 혼동행렬

학습에 쓰지 않은 30% 데이터로 채점해야 정직한 성능입니다
// AUC: 수주 딜 점수 > 실주 딜 점수일 확률 function auc(rows) { const pos = rows.filter(r => r.y); const neg = rows.filter(r => !r.y); let s = 0; pos.forEach(a => neg.forEach(b => { s += a.p > b.p ? 1 : a.p === b.p ? .5 : 0; })); return s / (pos.length * neg.length); }
// 임계값 th 이상이면 "수주 예상" function confusion(rows, th) { rows.forEach(r => { const hit = r.p >= th; c[hit ? (r.y ? 'tp' : 'fp') : (r.y ? 'fn' : 'tn')]++; }); c.prec = c.tp / (c.tp + c.fp); // 정밀도 c.rec = c.tp / (c.tp + c.fn); // 재현율 }
🎯 완성 예제 기준 검증 AUC는 약 0.87입니다(직접 만든 앱은 난수 구현 차이로 ±0.05 정도 달라질 수 있습니다). 임계값을 0.5 → 0.3으로 낮추면 놓치는 수주(FN)는 줄지만 헛된 기대(FP)가 늘어납니다. 영업 전략에 따라 "무엇을 더 싫어하는가"로 임계값을 정합니다.

핵심 기술 ③ — 승률 결합과 몬테카를로 매출 예측

단계 확률 + 딜 품질 점수 → 딜별 승률 → 5,000번 가상의 90일
// 단계 진척(75%)과 딜 품질(모델)을 로그 오즈로 결합 function winProb(d) { const q = quality(d); // 모델 점수 const sp = STAGES[d.stage].prob; // 단계 확률 return sigmoid(logit(q) + logit(sp) - logit(MODEL.base)); } // 슬립: 방치일·마감 경과가 클수록 다음 분기로 const slip = (.08 + .012 * 방치일 + (마감경과 ? .25 : 0)) * 민감도;
// 5,000회 반복: 딜마다 동전을 세 번 던진다 for (let i = 0; i < n; i++) { let t = 0; for (const x of deals) { const win = rng() < x.p; const slip = rng() < x.s; const disc = rng() * 2 * 평균할인; if (win && !slip) t += x.amount * (1 - disc); } rev[i] = t; } // 정렬 → P10·P50·P90, 목표 이상 비율 = 달성 확률
🎲 완성 예제 기준으로 같은 파이프라인이라도 AI 기준은 달성 확률 약 46%, 단계 확률 기준은 약 11%로 나옵니다. 두 값의 차이가 크면 단계 확률이 딜의 실제 상태를 못 따라가고 있다는 뜻입니다.

핵심 기술 ④ — 드래그 앤 드롭 칸반과 전환 퍼널

이벤트 위임 한 번으로 모든 카드·컬럼을 처리하고, 단계 이력으로 병목을 찾습니다

// 각 단계에 도달한 종료 딜 수 const reached = s => closed.filter(d => maxStage(d) >= s).length; // 전환율 = 다음 단계 도달 ÷ 현재 단계 도달 funnel[s].conv = reached(s + 1) / reached(s); // 가장 낮은 전환율 = 병목 const bottle = funnel.slice(0, 4) .reduce((a, b) => b.conv < a.conv ? b : a);

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 통계를 시키는 법"을 배웁니다

POINT 1 — 특성과 제외 대상을 목록으로

입력 특성 8개를 이름까지 적고, 단계는 결과를 누설하므로 빼라고 명시했습니다. 누설된 모델은 AUC가 0.99로 나오지만 실제로는 쓸모가 없습니다.

POINT 2 — 검증 방식까지 지정

"70/30 분할·표준화·L2 정규화"를 적었기 때문에 AI가 학습 데이터로 채점하는 흔한 실수를 하지 않습니다.

POINT 3 — 비즈니스 공식은 수식으로

승률 결합식과 슬립 공식을 숫자까지 적었습니다. "슬립을 반영해줘"라고만 하면 AI마다 공식이 달라져 결과를 비교할 수 없습니다.

POINT 4 — 사용성 요구를 기능처럼

"안내 바·툴팁·첫 방문 가이드·단축키"를 기능 목록에 넣었습니다. 쓰기 쉬운 앱은 저절로 나오지 않고, 요구해야 나옵니다.

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요
🧠 "AUC가 0.5 근처예요 / 0.99예요"

0.5면 숨은 승률 함수가 약하거나 특성이 결과와 무관한 것이고, 0.99면 단계가 특성에 들어간 누설입니다. 특성 목록을 콘솔에 출력해 달라고 하세요.

🔁 "새로고침하면 화면이 멈춰요"

회사명 조합 수보다 만들 딜이 많으면 중복 회피 루프가 끝나지 않습니다. "이름 조합 수가 딜 수보다 충분히 많게 해줘"라고 요청하세요.

🖱️ "카드가 끌리지 않아요"

카드에 draggable="true", 컬럼 dragover에서 e.preventDefault()가 있어야 놓을 수 있습니다. 이 두 줄을 확인해 달라고 하세요.

💾 "데이터를 처음으로 되돌리고 싶어요"

파이프라인 화면의 데이터 → 샘플 데이터로 초기화를 누르세요. localStorage에 저장된 변경 내용이 지워집니다.

🤖 만능 해결법: F12 → Console의 빨간 오류나 이상한 화면을 그대로 복사(캡처)해서 Antigravity에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요.
