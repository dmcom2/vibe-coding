오늘 나오는 용어 미리보기

외우지 마세요 — 눈에만 익혀 두면 수업이 술술 풀립니다

📌 사실 테이블 · 차원 · 측정값

판매 한 건(월 · 제품 · 채널 · 지역)마다 한 줄. 자르는 기준이 차원, 더하는 숫자(매출 · 이익 · 수량)가 측정값입니다.

📌 REST API · SQLite

화면이 POST /api/query로 "카테고리별 매출"을 요청하면 서버가 SQLite 파일 DB에 GROUP BY를 실행해 돌려줍니다.

📌 교차 필터 · 드릴다운

한 차트를 누르면 다른 차트도 함께 걸러지는 것이 교차 필터, 카테고리 → 제품처럼 한 단계씩 내려가는 것이 드릴다운.

📌 전년 동기 · 요인 분해

같은 달끼리 1년 전과 비교(계절 영향 제거). 매출 변화 = 수량 효과 + 제품 구성(믹스) 효과 + 가격 효과.

📌 계절 지수 · MAPE

그 달이 평소보다 얼마나 잘 팔리는지(12월 1.26 등). MAPE는 예측이 평균 몇 % 틀렸는지 — 작을수록 좋음.

📌 z점수 · 이상치

실적이 모형에서 표준편차 몇 배만큼 벗어났는지. |z| ≥ 2면 이상치 — 장애 · 대형 수주 같은 일회성 사건을 찾습니다.

핵심 기술 ① — Express 집계 API와 SQLite

화면은 "무엇을 어떻게 묶을지"만 보내고, 계산은 DB가 한다 — 단, 열 이름은 화이트리스트로만
// 판매 기록 한 줄 = 월 · 제품 · 채널 · 지역 db.exec(`CREATE TABLE IF NOT EXISTS sales ( month TEXT, product TEXT, category TEXT, channel TEXT, region TEXT, qty INTEGER, price REAL, rev REAL, cost REAL, profit REAL, PRIMARY KEY (month, product, channel, region))`); // 비어 있으면 data.js의 생성기로 3,456줄 넣기 if (count() === 0) seed();
app.post('/api/query', (req, res) => { // 열 이름은 정해진 목록에서만 (SQL 주입 방지) const dims = req.body.dims.filter(d => DIM_COLS.includes(d)); // 값은 전부 ? 자리표시자로 const where = buildWhere(req.body, params); const sql = `SELECT ${dims}, SUM(rev) rev, SUM(profit) profit, SUM(qty) qty FROM sales ${where} GROUP BY ${dims}`; res.json({ rows: db.prepare(sql).all(...params) }); });
🗄️ 완성 예제 기준 서버를 처음 켜면 SQLite에 3,456줄(24개월 × 제품 12 × 채널 3 × 지역 4)이 들어갑니다. 탐색 화면 아래에는 서버가 실제로 실행한 SQL이 그대로 표시되어, 필터를 바꿀 때마다 WHERE 절이 어떻게 달라지는지 볼 수 있습니다.

핵심 기술 ④ — 가격 · 수량 · 믹스 요인 분해

"매출이 10억 늘었다" 다음 질문은 "더 많이 팔았나, 비싼 걸 팔았나, 값을 올렸나?"
// 제품별 전기(0) · 당기(1) 수량 q, 단가 p = 매출 ÷ 수량 const avgP0 = R0 / Q0; // 전기 평균 단가 volume = (Q1 - Q0) * avgP0; // 수량 효과 for (const 제품 of 제품들) { const s0 = q0 / Q0; // 전기 구성 비중 mix += (q1 - Q1 * s0) * p0; // 믹스 효과 price += q1 * (p1 - p0); // 가격 효과 } // R0 + volume + mix + price === R1 (정확히 일치)
// 차원별 기여도: 이 항목이 전체 변화의 몇 %를 만들었나 function contrib(prev, cur, dim) { const total = sum(cur) - sum(prev); return 항목들.map(k => ({ d: cur[k] - prev[k], share: (cur[k] - prev[k]) / total, g: (cur[k] - prev[k]) / prev[k] })); } // 폭포 차트: 전년 → +수량 → +믹스 → +가격 → 당기

핵심 기술 ⑤ — 추세 × 계절 예측과 이상치

직선 추세에 달마다의 계절 지수를 곱한다 — 그리고 튀는 달에 모형이 끌려가지 않게 한다

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 풀스택 분석 도구를 시키는 법"을 배웁니다

POINT 1 — 파일마다 역할을 정한다

"서버와 화면이 같은 data.js를 쓴다"를 적어 두면, 서버 모드와 로컬 모드의 숫자가 어긋나는 가장 흔한 문제가 사라집니다.

POINT 2 — API의 모양을 먼저 적는다

요청 · 응답 예시(dims · from · to · filters → rows)를 주면 AI가 화면과 서버를 따로 만들어도 잘 맞물립니다.

POINT 3 — 보안 규칙을 명시한다

"열 이름은 화이트리스트, 값은 ? 자리표시자" 한 줄이 없으면 AI는 요청 값을 SQL 문자열에 그대로 이어 붙이기 쉽습니다(SQL 주입).

POINT 4 — 분석 공식을 식으로

"원인을 분석해줘" 대신 수량 · 믹스 · 가격 효과의 식과 "합이 변화액과 같아야 한다"는 검산 조건을 줬습니다.

✏️ 비교해 보기
❌ 막연한 요청

"필터를 받아서 DB에서 매출을 집계하는 API 만들어줘."

✅ 구체적인 요청

"POST /api/query { dims, from, to, filters } — 차원 이름은 화이트리스트로만 받고, 값은 모두 ? 자리표시자로 넘겨 SUM · GROUP BY 해줘."

자주 막히는 문제 & 해결법

여기서 멈추는 게 정상입니다 — 옆 사람도 같은 곳에서 막혀 있어요
🧱 "npm install에서 better-sqlite3 오류"

Node.js 버전이 너무 오래되었거나 너무 최신인 경우입니다. node -v로 LTS(v18~v22)인지 확인하고, 오류 전문을 Antigravity에 붙여넣으세요.

🚪 "EADDRINUSE: 3000 포트 사용 중"

다른 서버가 3000번을 쓰고 있습니다. 그 터미널을 Ctrl+C로 끄거나, PORT=3100 npm start(PowerShell은 $env:PORT=3100; npm start)로 바꿔 여세요.

🟡 "배지가 계속 '로컬 데모'예요"

파일을 더블클릭하거나 Live Server로 열면 API가 없어 로컬 모드가 됩니다. 반드시 http://localhost:3000으로 여세요.
