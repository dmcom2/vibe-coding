CSS Grid로 그리드/리스트 뷰 전환

grid-template-columns 한 줄만 바꾸면 레이아웃이 바뀝니다

/* 그리드 뷰: 4열 카드 */ .catalog-grid { display: grid; grid-template-columns: repeat(4, 1fr); gap: 14px; } /* 리스트 뷰: 1열 행형 */ .catalog-grid.list-view { grid-template-columns: 1fr; gap: 8px; } // JS: 클래스 토글로 전환 function setView(isGrid) { grid.classList.toggle( 'list-view', !isGrid ); }
Grid vs Flex

• Grid — 행·열 2차원 제어
→ 카드 갤러리, 대시보드

• Flex — 1차원 방향 제어
→ 헤더, 버튼 그룹, 리스트 행

카탈로그 카드 = Grid
헤더 레이아웃 = Flex

Array.filter()로 검색 & 카테고리 필터

배열의 filter() 메서드 하나로 검색과 카테고리를 동시에 처리

function getFiltered() { return ITEMS.filter(item => { // 카테고리 조건 const matchCat = currentCategory === '전체' || item.category === currentCategory; // 검색어 조건 const matchSearch = !currentSearch || item.id.includes(currentSearch) || item.name.includes(currentSearch); // 둘 다 만족해야 표시 return matchCat && matchSearch; }); }
filter() 동작 원리

배열의 각 항목에 조건 함수를 실행해
true를 반환하는 항목만 새 배열로 반환

→ 원본 배열(ITEMS)은 변경되지 않음
→ 검색할 때마다 원본에서 다시 필터링
→ 검색어·카테고리 상태만 바꾸고 re-render
✅ 상태(state) = currentCategory, currentSearch
✅ 렌더 = getFiltered() → DOM 업데이트
✅ 상태가 바뀔 때마다 렌더 함수 호출

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 잘 말하는 법"을 배웁니다

✅ POINT 1

기능을 영역별로 구조화

"카탈로그 UI · 품목 카드 · 샘플 데이터 · 기능"처럼 섹션을 나눠 요청하면 AI가 빠뜨리지 않고 전체를 구현합니다.

✅ POINT 2

데이터 구조를 미리 지정

"id, name, spec, category, status, price, unit, minOrder, leadTime, note 필드"처럼 필드명을 명시하면 AI가 임의로 결정하지 않습니다.

✅ POINT 3

UI 패턴 이름을 사용

"모달", "사이드패널", "배지"처럼 UI 패턴 이름을 쓰면 AI가 정확히 알아듣고 표준적인 구현을 제공합니다.

✅ POINT 4

출력 형식 명확히 지정

"index.html·style.css·script.js 3개로, 한국어 주석"처럼 결과물 형태를 지정하면 원하는 구조 그대로 파일을 만들어 줍니다.

핵심 코드 이해하기

localStorage로 출고요청 장바구니를 새로고침 후에도 유지하는 원리

// 앱 시작 시 localStorage에서 장바구니 복원 let cart = JSON.parse( localStorage.getItem('catalogCart') || '[]' ); // 담기: 이미 있으면 수량 +1, 없으면 새로 추가 function addToCart(id) { const existing = cart.find(c => c.id === id); if (existing) { existing.qty += 1; } else { cart.push({ id, qty: 1, /* ... */ }); } localStorage.setItem( 'catalogCart', JSON.stringify(cart) ); } // CSV 내보내기: Blob → 가상 a 태그 → 클릭 const blob = new Blob([csv], {type:'text/csv'}); const a = document.createElement('a'); a.href = URL.createObjectURL(blob); a.download = '출고요청서.csv'; a.click();

데이터를 JSON으로 분리하는 이유

catalog-data.json이 앱의 "데이터베이스" 역할을 합니다

📂 파일 구조 (4개)
05_카탈로그뷰어/ ├── index.html ← 화면 구조 ├── style.css ← 스타일 ├── script.js ← 기능 로직 └── catalog-data.json ← 품목 데이터 ★
🔄 데이터 로딩 우선순위
// 1순위: localStorage (앱에서 수정한 내용) // 2순위: catalog-data.json (원본 파일) // 3순위: DEFAULT_ITEMS (비상 내장 데이터) async function loadCatalog() { const saved = localStorage.getItem('catalogItems'); if (saved) { ITEMS = JSON.parse(saved); return; } try { const res = await fetch('./catalog-data.json'); ITEMS = (await res.json()).items; } catch { ITEMS = DEFAULT_ITEMS; } }
📝 품목 직접 수정
catalog-data.json을 텍스트 에디터에서 직접 편집 후 저장하고, 브라우저를 새로고침하면 반영됩니다.
📥 JSON 내보내기
앱에서 수정한 데이터를 catalog-data.json 형식으로 다운로드합니다. 이 파일로 원본을 교체하면 영구 반영됩니다.
↺ JSON 원본으로 초기화
localStorage를 클리어하고 catalog-data.json을 다시 불러옵니다. 실수로 잘못 수정했을 때 원상복구하는 버튼입니다.
💡 Go Live 필수! fetch()는 HTTP 서버가 있어야 동작합니다. file://로 직접 열면 catalog-data.json을 못 불러와 DEFAULT_ITEMS로 대체됩니다. 반드시 Go Live로 실행하세요.

즐겨찾기 기능

자주 쓰는 품목을 즐겨찾기에 등록해 빠르게 찾습니다.

카드 우상단 ⭐ 버튼 클릭으로 즐겨찾기 토글.
카테고리 탭에 "즐겨찾기" 탭 추가.
localStorage에 저장해 새로고침 후에도 유지.

수정 과제 — 단계별 완성

메인 프롬프트 완성 후 아래 5단계를 순서대로 요청해 완성형 앱을 만드세요

📊
과제 1 · 재고 관리

재고 현황 표시

stock 필드를 추가하고 카드에 현재고와 재고상태를 색상으로 표시합니다.

• 각 품목에 stock 필드 추가
• 카드에 재고상태 배지 (In/Low/Out of Stock)
• 현재고 수치 색상 표시 (초록/노랑/빨강)
• 상단 요약 카드: 전체/정상/부족/없음 건수
💬 "품목에 stock 필드 추가, 카드에 재고상태 배지와 현재고 수치 색상 표시, 상단에 재고 현황 요약 카드 만들어줘"
🛒
과제 2 · 출고요청

출고요청 + 담기 패널

카드에 수량 입력 필드와 담기 버튼을 추가하고 사이드패널로 관리합니다.

• 카드에 수량 입력 + 담기 버튼
• 헤더 뱃지로 담긴 수량 표시
• 사이드패널: 수량 조정 + CSV 다운로드
• localStorage로 새로고침 후에도 유지
💬 "카드에 수량 입력 필드와 담기 버튼 추가, 헤더 뱃지 표시, 출고요청 사이드패널에서 수량 조정·CSV 다운로드 구현, localStorage 저장해줘"
✅
과제 3 · 핵심 로직

출고 확정 + 이력 관리

출고 확정 시 실재고가 줄고 상태가 자동 변경, 이력이 기록됩니다.

• 출고요청 패널에 "출고 확정" 버튼
• 확정 시 stock 차감 + 상태 자동 재판정
• 헤더 "출고이력" 버튼 + 이력 사이드패널
• 이력: 날짜·품목·차감 수량·전후 재고
💬 "출고 확정 기능 추가(stock 차감 + 상태 자동 재판정), 출고이력 사이드패널 구현(날짜·품목·차감 수량·전후 재고), localStorage 저장해줘"
🔐
과제 4 · 관리자 시스템

관리자 모드 + 제품 CRUD

비밀번호 인증 후 제품을 직접 추가·수정·삭제할 수 있는 관리자 모드입니다.

• 헤더 "관리자" 버튼 → 비밀번호 모달 (1234)
• 관리자 바: 제품 추가 버튼
• 카드에 수정·삭제 버튼 표시
• 추가·수정: 폼 모달 (10개 필드), localStorage 저장
💬 "비밀번호(1234) 인증 관리자 모드 추가, 관리자 바에 제품 추가 버튼, 카드에 수정·삭제 버튼, 추가·수정·삭제 폼 모달, localStorage 저장해줘"
📁
과제 5 · 데이터 관리

JSON 파일 데이터 관리

품목 데이터를 JSON 파일로 분리해 외부에서 편집하고 앱에서 내보낼 수 있습니다.

• catalog-data.json 파일로 데이터 분리
• 앱 시작 시 fetch('./catalog-data.json') 로딩
• localStorage에 변경사항 캐시
• 관리자 바: JSON 내보내기 + JSON 원본으로 초기화
💬 "품목 데이터를 catalog-data.json으로 분리, fetch 로딩 + localStorage 캐시, 관리자 바에 JSON 내보내기·초기화 버튼 추가, 파일 4개 구조로 변경해줘"
