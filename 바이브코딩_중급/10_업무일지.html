📌 REST API

GET·POST·PATCH·DELETE 요청으로 서버 데이터를 읽고·만들고·수정하고·삭제하는 통신 방식

📌 fetch()

브라우저에서 서버로 요청을 보내고 응답을 받는 내장 함수. await fetch('/api/tasks') 처럼 사용

📌 JSON 파일 저장

서버가 데이터를 data/ 폴더의 .json 파일에 읽고 쓰는 방식. 팀원 모두가 같은 파일을 공유

📌 배열 filter · find

배열에서 조건을 만족하는 항목만 골라내는 메서드. 특정 담당자·상태 업무 필터링에 사용

📌 .env 파일

API 키 같은 민감한 정보를 코드 밖에 보관하는 파일. process.env.GEMINI_API_KEY 로 읽음

📌 SSE 스트리밍

AI 응답을 한 글자씩 실시간으로 브라우저에 흘려주는 방식. ChatGPT처럼 타이핑 효과가 나타남

🌱 낯선 단어가 나와도 괜찮습니다. 코드는 AI가 쓰고, 우리는 읽고 요청만 하면 돼요!

tasks.json — 업무 데이터 구조

서버가 data/tasks.json 파일에 배열로 저장하는 업무 객체 한 개

// data/tasks.json — 업무 배열 (한 항목의 구조) [ { "id": "uuid-abc123", // 고유 ID "title": "기획서 작성", "assignee": "홍길동", // 담당자 "status": "진행중", // 미처리·진행중·완료 "priority": "높음", // 높음·보통·낮음 "startDate": "2025-06-01", "endDate": "2025-06-05" }, { ... } ] // server.js — 배열 읽기 / 쓰기 패턴 function read(file) { return JSON.parse(fs.readFileSync(file, 'utf8')); } function write(file, data) { fs.writeFileSync(file, JSON.stringify(data, null, 2)); }
data/ 폴더 파일 5개

• tasks.json — 업무 목록
• members.json — 팀원 배열
• notice.json — 공지사항 텍스트
• history.json — 변경 이력 배열
• absences.json — 부재 일정
history.json 이력 한 개

{
"at": "2025-06-01T09:00:00Z",
"name": "홍길동",
"action": "기획서 작성 → 완료"
}

Express 라우터 — URL이 곧 기능

server.js가 브라우저 요청을 받아 JSON 파일을 읽고·쓰는 구조

// server.js — 업무 관련 라우터 예시 // GET /api/tasks → tasks.json 전체 읽기 app.get('/api/tasks', (req, res) => { res.json(read(TASKS_FILE)); }); // POST /api/tasks → 새 업무 추가 후 저장 app.post('/api/tasks', (req, res) => { const tasks = read(TASKS_FILE); tasks.push({ ...req.body, id: uuid() }); write(TASKS_FILE, tasks); res.json({ ok: true }); }); // PATCH /api/tasks/:id → 상태 수정 + 이력 기록 app.patch('/api/tasks/:id', (req, res) => { const tasks = read(TASKS_FILE); const task = tasks.find(t => t.id === req.params.id); Object.assign(task, req.body); write(TASKS_FILE, tasks); appendHistory(task, req.body.status); res.json({ ok: true }); }); // DELETE /api/tasks/:id → 해당 업무 삭제 app.delete('/api/tasks/:id', (req, res) => { let tasks = read(TASKS_FILE); tasks = tasks.filter(t => t.id !== req.params.id); write(TASKS_FILE, tasks); res.json({ ok: true }); });

GET — 읽기 (Read)

파일에서 데이터를 읽어 JSON으로 응답.
브라우저가 페이지 로드 시 호출.

POST / PATCH — 쓰기 (Write)

body에 담긴 데이터를 받아 파일에 저장.
PATCH는 일부만, POST는 새 항목 추가.

DELETE — 삭제 (Delete)

URL의 :id를 기준으로 배열에서 제거 후
파일을 다시 저장.

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 잘 말하는 법"을 배웁니다

✅ POINT 1

레이아웃을 텍스트로 그려라

[왼쪽 사이드바] / [오른쪽 메인 영역]처럼 화면 구조를 글로 묘사하면 AI가 정확한 2컬럼 레이아웃을 만든다. 머릿속 그림을 언어로 옮기는 것이 핵심이다.

✅ POINT 2

기능은 목록으로 낱낱이 나열

"날짜별 목록", "기분 선택", "자동저장"처럼 기능을 bullet으로 하나씩 나열하면 AI가 빠짐없이 모두 구현한다. 한 덩어리로 설명하면 일부가 누락된다.

✅ POINT 3

구현 방법은 몰라도 된다

"팀원별로 업무를 관리해줘"처럼 무엇을(what)만 설명하면 어떻게(how — Node.js 라우팅, JSON 파일 구조)는 AI가 스스로 설계한다. 기술 용어를 몰라도 기능 관점으로만 요청하면 충분하다.

✅ POINT 4

출력 형식 조건을 끝에 명시

"4개 파일로 나눠줘" + "한국어 주석 달아줘"처럼 결과물 형식을 마지막에 지정하면 나중에 수정·관리하기 좋은 코드를 받는다.

🆚 막연한 요청 vs 구체적인 요청의 차이

❌ 막연한 요청
"팀 업무 관리 앱 만들어줘"
→ 단순 목록, 저장 없음, 단일 파일
✅ 구체적인 요청
"종합 뷰 + 탭 구조 + JSON 파일 저장 + 부재 관리 + AI 보고서 + 4개 파일로 분리"
→ 한 번에 원하는 결과

package.json & package-lock.json

Node.js 프로젝트의 "재료 목록표" — 처음 한 번 만들면 다음부터는 npm install 한 줄로 끝

📄 package.json — 프로젝트 정보 + 패키지 목록

# ① 터미널에서 한 번만 실행 (자동 생성)
npm init -y

# ② 패키지 설치 (package.json에 자동 기록)
npm install express
npm install dotenv
package.json 역할
• 프로젝트 이름·버전·설명 기록
• express, dotenv 같은 패키지 목록이 자동 추가됨
• 협업 시 이 파일 하나만 있으면 npm install로 전체 복원 가능

🔒 package-lock.json — 정확한 버전 잠금 파일

자동으로 생성됩니다 — 직접 건드리지 마세요

npm install을 실행하면 자동으로 생성되며, 설치된 패키지의 정확한 버전 번호를 기록합니다. 다른 사람이 같은 프로젝트를 받았을 때 똑같은 버전의 패키지가 설치되도록 보장합니다.
💡 node_modules 폴더
실제 패키지 코드가 저장되는 폴더. 용량이 크므로 공유하지 않고, package.json만 공유 후 npm install로 각자 설치합니다.
✅ 이 프로젝트 설정 순서
npm init -y → npm install express → npm install dotenv → node server.js

서버 실행 방법

AI가 만든 코드를 실행하는 4단계 — Go Live 대신 node server.js

1

서버란 무엇인가? — Node.js + Express

브라우저가 요청하면 서버가 데이터를 돌려주는 구조

❌ 서버 없음 (localStorage)

데이터가 내 브라우저에만 저장됨
다른 PC에서 열면 데이터 없음
→ 혼자만 쓸 수 있는 앱

✅ 서버 있음 (Node.js + Express)

데이터가 서버 파일(JSON)에 저장됨
팀원 누구나 같은 데이터 접근
→ 팀이 함께 쓰는 앱

// server.js — Express 5 서버 핵심 구조 const express = require('express'); const app = express(); app.use(express.json()); app.use(express.static('.')); // index.html, style.css, script.js 자동 서빙 // 브라우저가 GET /api/tasks 요청 → tasks.json 파일 내용 반환 app.get('/api/tasks', (req, res) => res.json(readJSON('tasks.json'))); app.listen(7823, () => console.log('서버 실행: http://localhost:7823'));
💡 핵심 개념: 브라우저(front)가 fetch('/api/tasks')를 호출 → 서버(back)가 JSON 파일을 읽어 응답. AI에게 "Node.js + Express 서버 기반으로 만들어줘"라고 하면 이 구조를 자동으로 설계해 줍니다.

JSON 파일로 데이터를 저장하는 방법

DB 설치 없이 파일 하나로 데이터를 유지하는 초보자 친화 구조

📂 data/
 ├─ tasks.json
 ├─ members.json
 ├─ notice.json
 ├─ history.json
 └─ absences.json
tasks.json  업무 배열 — 제목, 담당자, 상태(미처리/진행중/완료), 기간, 우선순위
members.json  팀원 이름 배열 — ["홍길동", "김연아", "이철수", "박영희", "조용필"]
history.json  변경 이력 배열 — 일시, 담당자, 변경 내용 (업무 변경 시 자동 기록)
absences.json  날짜 키 구조 — {"2025-06-10": [{name, reason}]}
💡 왜 JSON 파일인가? MySQL·MongoDB 같은 별도 DB 설치가 필요 없습니다. 파일을 직접 열어보면 데이터 구조를 바로 확인할 수 있고, AI가 파일 읽기/쓰기 코드를 자동으로 생성해 줍니다.

[기술 스택] - 서버: Node.js, Express 5, 포트 7823 - 데이터: data/ 폴더 JSON 파일 (tasks.json, members.json, notice.json, history.json, absences.json) - AI: Google Gemini API (gemini-3.5-flash-light), 환경변수 GEMINI_API_KEY, SSE 스트리밍 응답 - 파일 구성: server.js, index.html, style.css, script.js [메인 화면 — 종합 뷰] - 상단 GNB: 오늘 날짜, 공지사항(클릭 수정), 접속자 수, 오늘 부재자 이름(사유) 자동 표시 - 중간 2컬럼: 왼쪽(오늘 기한 업무, 1줄 표시, 오버플로 스크롤), 오른쪽(실시간 변경 이력 + 나의 업무 요약: 미처리/진행중/완료 가로 3칸) - 하단: 팀원별 업무 현황 카드 그리드 (미처리/진행중/완료 건수 배지, 부재 시 배지 표시) - 카드 클릭 → 해당 팀원 상세 뷰, 담당자 카드에 [📝 업무 일지] 버튼 [업무 관리] - 업무 필드: 제목, 담당자, 시작일, 종료일, 우선순위(높음/보통/낮음), 상태(미처리/진행중/완료) - 업무 추가/수정/삭제, 상태 원클릭 변경 (미처리→진행중→완료 순환) - 업무 변경 시 history.json에 이력 자동 기록 (일시, 담당자, 변경 내용) [부재 관리 — 미션 1] - 설정 탭: 날짜 + 팀원 + 사유(연차/반차/출장/사외교육/기타) 조합으로 부재 일정 등록/삭제 - 오늘 부재자 GNB에 이름(사유) 형태로 자동 표시 - 종합 뷰 팀원 카드에 부재 배지 자동 표시 - absences.json 구조: { "날짜": [{ name, reason }] } [데이터 백업/복원 — 미션 2] - 설정 탭: [💾 백업 다운로드] → 모든 JSON 파일을 하나로 묶어 backup_날짜.json으로 다운로드 - [📂 백업 복원] → JSON 파일 선택 시 모든 데이터 파일 복원 후 화면 갱신 [AI 기능 — 미션 3·4·5·6] API 키: 서버 환경변수 GEMINI_API_KEY (클라이언트 노출 금지) 응답: SSE(Server-Sent Events) 스트리밍으로 실시간 텍스트 출력 POST /api/ai/daily — 일간 보고서 (미션 3) 오늘 전체 업무(상태/우선순위) + 부재자 정보를 AI에 전달 팀장 보고용 일간 업무 현황 보고서 자동 작성 POST /api/ai/weekly — 주간 보고서 (미션 4) 최근 7일 history.json 이력 + 현재 전체 업무 목록을 AI에 전달 주간 단위 팀 성과·완료 항목 요약 보고서 자동 작성 POST /api/ai/work-log — 개인 업무 일지 (미션 5) body: { name: "팀원명" } 해당 팀원 업무(상태별) + 최근 변경 이력을 AI에 전달 개인 업무 일지 형식 작성 (오늘 한 일·진행 중·이번 주 완료) 담당자 카드 [📝 업무 일지] 버튼에서 호출 POST /api/ai/member-insight — 개인 현황 정리 (미션 6) body: { name: "팀원명" } 해당 팀원 전체 업무를 AI가 분석해 현황 요약 보고서 작성 AI 탭 개인 현황 패널 [🤖 현황 정리] 버튼에서 호출 [AI 탭 UI] - 팀 분석 패널: [📅 일간 보고서] [📊 주간 보고서] 버튼 → 우측 결과창에 SSE 스트리밍 출력 - 개인 현황 패널: 팀원 선택 드롭다운 + [🤖 현황 정리] 버튼 - 결과창: 마크다운 → HTML 변환 렌더링, [복사] 버튼 제공 [설정] - 팀원 목록 추가/삭제 (기본: 홍길동, 김연아, 이철수, 박영희, 조용필) - 공지사항 수정, 나의 이름 설정 파일은 server.js, index.html, style.css, script.js 4개로 나눠서 만들고, 한국어 주석 달아줘.
