위젯 그리드 & 드래그 앤 드롭

dragstart → dragover → drop, 3개의 이벤트로 위젯 순서를 바꿉니다

const grid = document.getElementById('grid'); let dragSrc = null; // 위젯을 잡는 순간 grid.addEventListener('dragstart', e => { dragSrc = e.target.closest('.widget'); e.dataTransfer.effectAllowed = 'move'; }); // 다른 위젯 위를 지나가는 동안 grid.addEventListener('dragover', e => { e.preventDefault(); // 기본 동작을 막아야 drop 가능 const target = e.target.closest('.widget'); if (target && target !== dragSrc) { target.classList.add('drag-over'); } }); // 손을 놓는 순간 — 실제로 자리 교환 grid.addEventListener('drop', e => { e.preventDefault(); const target = e.target.closest('.widget'); if (!target || target === dragSrc) return; const next = dragSrc.nextSibling; target.after(dragSrc); if (next) next.before(target); else grid.append(target); });
왜 이벤트가 3개나 필요할까요?

① dragstart — 어떤 위젯을 잡았는지 기억
② dragover — 브라우저 기본 동작(드롭 금지)을 막아야 drop이 실행됨
③ drop — 실제로 DOM에서 두 위젯의 위치를 맞바꿈
🎯

draggable="true"

HTML에서 각 .widget에 이 속성이 있어야 드래그가 가능합니다. index.html의 위젯 6개 모두에 붙어있어요.

실적 저장 & 마감일 D-day 계산

실적을 저장하면 달성률과 차트가 함께 갱신되고, 마감일은 오늘과의 날짜 차이로 계산합니다

JS // ① 실적 저장 — 달성률과 월별 차트를 함께 갱신 function savePerf() { const target = Number(...perf-target.value) || 0; const actual = Number(...perf-actual.value) || 0; perf = { target, actual }; localStorage.setItem('dash_perf', JSON.stringify(perf)); renderPerf(); updateChart(); // 차트의 "이번달" 막대도 함께 갱신 } // ② 마감일까지 남은 일수를 D-day로 표시 function ddayLabel(due) { const today = new Date(); today.setHours(0,0,0,0); const diff = Math.round((new Date(due) - today) / 86400000); if (diff === 0) return 'D-DAY'; return diff > 0 ? `D-${diff}` : `D+${-diff}`; // 지났으면 D+n }

두 함수의 공통점과 차이

savePerf — 저장 시 연쇄 갱신

실적을 저장하면 달성률(%)뿐 아니라 월별 매출 차트의 마지막 막대까지 함께 다시 그립니다

ddayLabel — 날짜 뺄셈으로 계산

날짜끼리 빼면 밀리초가 나오므로, 하루(86400000ms)로 나눠 "며칠 남았는지"를 구합니다

09번 월간 캘린더와 같은 원리

중급 09의 Date 계산 패턴이 여기서 마감일 D-day 계산에 그대로 재사용됩니다

여러 API를 한 번에 — Promise.all

fetch 여러 개를 동시에 보내고, 모두 끝나면 한꺼번에 결과를 받는 패턴

// fetch를 병렬로 호출해 모든 데이터를 한 번에 받기 async function loadAllData() { try { const [weatherData, rateData] = await Promise.all([ fetch(WEATHER_URL).then(r => r.json()), fetch(RATE_URL).then(r => r.json()), ]); updateWeatherWidget(weatherData); updateRateWidget(rateData); } catch (err) { console.error('API 호출 실패:', err); loadFromCache(); // 실패 시 캐시 데이터 사용 } }
지금 대시보드는 환율 API 1개만 부르지만, 미션 1(날씨 위젯)을 추가하면 환율 + 날씨, API 2개를 동시에 부르게 되어 이 패턴이 그대로 필요해집니다.
⏳

Promise.all의 장점

fetch를 순서대로 하나씩 기다리면 느립니다. Promise.all([...])은 여러 요청을 동시에 보내고 가장 늦게 끝나는 것 하나만 기다리면 됩니다.

Chart.js로 월별 매출 추이 그리기

과거 5개월 이력 + 실적 위젯의 이번달 값을 이어 붙여 막대 차트로 표시

JS let revenueChart = null; let history = JSON.parse(localStorage.getItem('dash_history') || '[...]'); function updateChart() { const data = [...history, perf.actual]; // 과거 5개월 + 이번달(실적 위젯과 연동) if (revenueChart) { // 이미 그려진 차트가 있으면 데이터만 교체 revenueChart.data.datasets[0].data = data; revenueChart.update(); return; } revenueChart = new Chart(document.getElementById('revenue-chart'), { type: 'bar', data: { labels: MONTH_LABELS, datasets: [{ label: '매출', data, backgroundColor: '#6366f1', borderRadius: 6 }] }, options: { responsive: true, maintainAspectRatio: false, plugins: { legend: { display: false } } } }); }
💡 실적 위젯에서 "저장"을 누를 때마다 perf.actual이 바뀌고, updateChart()가 그 값을 이번달 막대에 그대로 반영합니다. 두 위젯이 하나의 데이터를 공유하는 셈입니다.

①
무엇을 "팀 업무 실적 대시보드를 만들어줘"
만들 것을 한 문장으로. 첫 줄이 가장 중요합니다
②

③

프롬프트 해설 — 왜 잘 작동했을까?

앞 슬라이드 프롬프트를 분석해 "AI에게 잘 말하는 법"을 배웁니다

✅ POINT 1

번호를 매겨 위젯을 나열했다

①~⑥처럼 번호를 붙여 기능을 하나씩 나열하면 AI가 항목을 빠뜨리지 않고 순서대로 만들어줍니다. 위젯이 많을수록 목록화가 핵심입니다.

✅ POINT 2

라이브러리 이름을 직접 명시했다

"Chart.js CDN", "exchangerate-api.com"처럼 쓸 도구를 이름까지 지정하면 AI가 제멋대로 다른 라이브러리를 선택하지 않아 예측 가능한 결과가 나옵니다.

✅ POINT 3

파일 분리 조건을 명시했다

"index.html, style.css, script.js 3개로 나눠줘"라고 하면 AI가 하나의 큰 파일이 아닌 역할별로 분리된 구조를 만들어 이후 수정이 훨씬 쉬워집니다.

✅ POINT 4

저장 방식을 조건으로 못 박았다

"localStorage로 모든 데이터 저장"이라고 명시하면 새로고침 후에도 데이터가 유지되는 앱이 보장됩니다. 조건을 빠뜨리면 새로고침 시 데이터가 날아가는 코드가 나올 수 있습니다.

🆚 막연한 요청 vs 이 프롬프트의 차이

❌ 막연한 요청
"업무 대시보드 만들어줘"
→ 위젯 구성·파일 구조·저장 방식이 AI마다 달라져 결과가 제각각
✅ 구체적인 요청
"위젯 6개를 ①~⑥으로 나열, Chart.js CDN, 3개 파일 분리, localStorage 저장"
→ 한 번에 원하는 결과

index.html · style.css · script.js 3개 파일이 같은 폴더에 있는지, 파일명이 정확한지 확인하세요.

💾 "고쳤는데 화면이 그대로예요"

수정한 모든 파일을 저장(Ctrl+S)하세요. 탭 이름 옆 ● 표시는 저장 안 됨 표시! 저장 후 브라우저 새로고침(F5).

📡 "환율이나 차트가 안 나와요"

환율 API와 Chart.js CDN 모두 인터넷 연결이 필요합니다. F12 → Console의 빨간 오류를 복사해 AI에게 붙여넣으세요.

🖱️ "위젯을 드래그해도 순서가 안 바뀌어요"

위젯 div에 draggable="true" 속성이 있는지, 입력창이 아니라 위젯의 빈 공간(헤더 부분)을 잡고 드래그하는지 확인하세요.

🤖 만능 해결법: 오류 메시지나 이상한 화면을 그대로 복사(캡처)해서 AI에게 "이거 왜 안 돼? 고쳐줘"라고 붙여넣으세요. 대부분 해결됩니다.

테마 전환 & localStorage 키 설계

위젯마다 독립된 저장 공간(key)을 가져서 서로 데이터가 섞이지 않습니다

// data-theme 속성으로 라이트/다크 분기 let theme = localStorage.getItem('dashboard_theme') || 'dark'; document.documentElement.setAttribute('data-theme', theme); function toggleTheme() { theme = theme === 'dark' ? 'light' : 'dark'; document.documentElement.setAttribute('data-theme', theme); localStorage.setItem('dashboard_theme', theme); } /* CSS 쪽에서는 변수만 교체하면 끝 */ /* [data-theme="light"] { --bg:#f1f5f9; --surface:#fff; } */

위젯별 localStorage 키

dashboard_theme — 다크/라이트 테마
dash_perf — 목표/실적
dash_todos — 할 일 목록 (마감일 포함)
dash_notices — 공지사항
dash_reps — 담당자별 실적
💡 위젯마다 key를 따로 두면, 한 위젯의 데이터가 망가져도 다른 위젯에 영향을 주지 않습니다.

직접 수정 미션

AI에게 요청해서 기능을 추가해보세요

⭐

미션 1
할 일 마감 필터

할 일 위젯에 "오늘 / 이번 주 / 전체" 필터 탭을 추가해서 마감 임박 항목만 골라볼 수 있게 합니다.

today/week/all 필터 상태 변수.
마감일과 오늘 날짜 비교.
filter()로 항목 걸러서 렌더링.
⭐⭐

미션 2
위젯 순서 저장

드래그로 바꾼 위젯 순서를 localStorage에 저장해서 새로고침 후에도 순서가 유지되도록 합니다.

drop 이벤트 후 querySelectorAll.
순서 배열을 localStorage 저장.
페이지 로드 시 순서 복원.
⭐⭐⭐

미션 3
실적 데이터 내보내기

담당자별 실적·목표·달성률 데이터를 CSV 파일로 다운로드하는 버튼을 순위 위젯에 추가합니다.

BOM + 헤더 행 + 데이터 행 조립.
Blob → createObjectURL.
a 태그 click()으로 다운로드.
