왜 한 번에 만들지 않고 5단계로 나눌까요?

초보자가 복잡한 프로그램을 만들 때 겪는 가장 흔한 어려움과 해결책

❌ 한 번에 만들면 생기는 문제

①프롬프트가 너무 길어지면 AI가 일부 기능을 빠뜨립니다
②오류가 나도 어디서 잘못됐는지 찾기가 매우 어렵습니다
③코드 길이가 2,000줄 이상이라 AI가 수정 요청을 받아도 엉뚱한 부분을 고칩니다
④무엇을 배운 건지 알 수 없어서 다음에 응용하기 어렵습니다

✅ 5단계로 나누면 좋은 점

①각 단계가 짧고 명확해서 AI가 빠짐없이 만들어줍니다
②단계마다 실행해서 바로 확인하니 오류를 빠르게 잡습니다
③"이전 코드 기반으로 추가"라고 하면 AI가 맥락을 유지합니다
④각 단계에서 새로운 개념 하나씩 익히니 실력이 쌓입니다
레고 블록으로 생각해보세요

완성된 레고 성을 한 번에 만들라고 하면 막막합니다.
하지만 기초 → 벽 → 지붕 → 장식 순으로 쌓으면
초보자도 완성할 수 있습니다.

코딩도 똑같습니다. 기본 틀 → 서버 → 로그인 → 기능 → AI 순서로 하나씩 쌓아 올리면 어떤 복잡한 프로그램도 만들 수 있습니다.

각 단계는 독립적으로 실행 가능한 완성 상태입니다 — 단계마다 브라우저에서 확인하세요

Gemini AI 보고서 생성 (SSE 스트리밍) Gemini API 연동, 업무 데이터 → AI 분석 → 보고서 실시간 출력. 일간·주간·커스텀 보고서, TXT·HTML 다운로드.
AI 기능

1단계 — HTML / CSS / JS 기본 틀

서버 없이 브라우저에서 바로 열 수 있는 대시보드 UI를 먼저 완성합니다

📌 이 단계에서 배우는 것

HTML이 뼈대(구조), CSS가 옷(디자인), JavaScript가 행동(동작)입니다. 이 세 파일을 분리해서 관리하면 나중에 수정이 훨씬 편리합니다.

🏗️ 비유로 이해하기
HTML = 건물의 뼈대
CSS = 인테리어와 색상
JavaScript = 엘리베이터, 자동문 같은 동작

아직 "서버"가 없으니 마치 모델하우스처럼 — 보기 좋게 꾸며진 빈 집입니다. 데이터는 JS 안에 직접 써넣은 샘플을 씁니다.
이 단계 완료 시 확인 항목
  • index.html을 브라우저에서 열면 로그인 화면이 보임
  • 아무 아이디나 입력하고 로그인하면 대시보드가 보임
  • KPI 숫자, Chart.js 도넛 차트, 담당자 카드가 샘플 데이터로 표시됨
  • 다크/라이트 모드 전환 버튼이 작동됨

📁 이 단계에서 생성되는 파일

📄index.html — 화면 구조 (로그인, 헤더, 탭, 카드)
🎨style.css — 색상, 카드, 배지, 다크모드, 반응형 레이아웃
⚙️script.js — 샘플 데이터 + 화면 렌더링 + 차트 로직

🚦 실행 방법

① Antigravity에서 index.html 파일 우클릭
② "Open with Live Server" 클릭
③ 브라우저 자동 실행 확인

4단계 — 업무 CRUD 모달 + 상태 변경 이력

업무를 직접 등록·수정·삭제하고, 상태 변경 이력이 자동으로 기록됩니다

📌 CRUD란 무엇인가요?

CRUD는 소프트웨어가 데이터를 처리할 때 사용하는 Create(생성), Read(조회), Update(수정), Delete(삭제)의 앞 글자를 딴 약자입니다. 모든 데이터 관리 시스템의 기본 4가지 동작입니다. 스마트폰 연락처 앱도 CRUD입니다 — 추가/보기/수정/삭제가 바로 그것입니다.

📌 이력(History)이 왜 필요한가요?

업무 상태가 "미처리 → 진행 중 → 완료"로 변할 때 누가, 언제 바꿨는지 기록하면 나중에 진행 상황을 추적할 수 있습니다. 팀장이 "이 업무 언제 시작했어?"라고 물어볼 때 바로 답할 수 있습니다.

이 단계 완료 시 확인 항목
  • 업무 등록 버튼 클릭 → 모달 팝업 → 저장 → 목록에 추가됨
  • 업무 클릭 → 수정 모달 → 상태 변경 → 이력에 기록됨
  • KPI 숫자와 도넛 차트가 변경 즉시 갱신됨
  • 마이 위젯에 내 담당 업무 D-day 표시됨

5단계 — Gemini AI 보고서 생성 (SSE 스트리밍)

AI가 업무 데이터를 분석해서 보고서를 실시간으로 작성해줍니다

📌 이 단계에서 배우는 것

Gemini AI에게 업무 데이터를 전달하면 AI가 이를 분석해 보고서를 씁니다. 보고서가 실시간으로 한 글자씩 나타나는 것은 SSE(Server-Sent Events) 기술 덕분입니다. 마치 AI가 직접 타이핑하는 것처럼 보입니다.

📡 SSE란 무엇인가요?

일반 fetch: 서버가 응답 완성 후 한 번에 전달
SSE: 서버가 조각조각 나눠서 실시간으로 전달

채팅 AI(ChatGPT, Claude)에서 답변이 타이핑되듯 나오는 것이 SSE입니다. 이 단계에서 같은 기술을 직접 구현합니다.

✅ 이 단계 완료 시 확인

• "AI 보고서" 버튼 클릭 → 설정 모달 표시
• 기간·담당자 선택 후 생성 → 보고서가 실시간으로 나타남
• 완료 후 TXT 또는 HTML 다운로드 확인
• .env에 API 키 없으면 안내 메시지 표시

🔑 API 키 발급 방법 (무료)

① aistudio.google.com 접속
② 구글 계정으로 로그인
③ "Get API key" 클릭 → "Create API key"
④ 발급된 키 복사
⑤ 프로젝트 폴더의 .env 파일에 추가:
GOOGLE_AI_API_KEY=여기에붙여넣기
